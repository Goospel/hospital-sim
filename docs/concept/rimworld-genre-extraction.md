# 림월드 장르 해부 — 조작·UI·흐름 추출과 이식 판정

> **목적(사용자 지시 2026-07-29)**: *"림월드의 게임적 요소들을 파악해. 조작방법, UI배치, 대략적인 게임흐름을 파악하고 우리 게임에 녹일 수 있는 부분을 추출해. 우리 게임이 전달하고자 하는 메시지도 고려해서 추출하도록 해. 림월드의 장르만 배껴온다는 생각으로 진행하라."*
>
> 이 문서는 림월드를 **장르 원형**으로 삼아 네 축(조작 · UI 배치 · 게임 흐름 · 서사 기계)으로 해부하고, 요소마다 **채택 / 변형 채택 / 기각**을 판정한다. 판정 기준은 §0의 메시지 렌즈 하나다. 구현 스펙이 아니라 **추출 카탈로그**다 — 여기서 채택된 항목이 이후 설계(`docs/superpowers/specs/`)로 내려간다.
>
> 선행 문서: [2026-07-27 림월드형 전면 재설계](../superpowers/specs/2026-07-27-rimworld-like-redesign-design.md)가 이미 재미 4요소(자율 폰 · 건설 · 위기 이벤트 · 개성 서사)를 이식했다. 이 문서는 그 나머지 — **화면 문법과 리듬** — 을 마저 훑는 2차 추출이다.

---

## 0. 판정 기준 — 메시지 렌즈

우리 게임의 논지는 하나다: **"개인이 최선을 다해도 구조 때문에 나쁜 결과가 나온다"** ([game-intro.md](../submission/game-intro.md) §1). 림월드와 우리는 같은 기계를 다른 결론에 쓴다:

| | 림월드 | 심스피탈 |
|---|---|---|
| 역경의 의미 | **이야기가 된다** (스토리 생성기) | **구조의 증언이 된다** |
| 상실의 서사 | 극복·회복의 재료 (무덤을 짓고 다시 일어선다) | 반복되는 필연 (풀은 줄기만 하고, 떠난 사람은 안 돌아온다) |
| 잘하면? | 위협이 커지되 **끝내 탈출한다** (우주선 엔딩) | 잘해도 **구조는 그대로다** (엔딩은 쟁취가 아니라 필연) |

그래서 판정 규칙 세 줄:

1. **"사람을 사람으로 보게 만드는" 장치는 최우선 채택** — 익명 통계를 개인으로 바꾸는 것이 이 게임의 존재 이유다.
2. **"플레이어가 구조를 이길 수 있게 만드는" 장치는 기각** — 정답 배치·성장 해금·직접 개입은 "잘하면 되잖아"를 만들고, 그 순간 메시지가 정반대로 뒤집힌다.
3. 나머지는 **화면 문법**이다 — 장르 관습이 편의를 주면 마감(8/10) 안에서 채택한다.

## 1. 림월드 해부

### 1-1. 조작 문법 — 간접 통제가 뼈다

| 요소 | 림월드의 방식 |
|---|---|
| **통제 원칙** | 폰을 직접 조종하지 않는다. 우선순위 표·구역·배치로만 개입 — 폰이 스스로 판단해 움직인다 |
| **유일한 예외** | **드래프트(징집)** — 전투 시 폰을 직접 클릭-이동시키는 모드. 간접 통제의 의도적 구멍 |
| 시간 | 스페이스 = 일시정지 토글, 숫자 1·2·3 = 배속. **사건이 터지면 자동 일시정지**(중대사건만) |
| 선택·조사 | 좌클릭 선택 → 좌하단 인스펙트 패널. 드래그 박스 다중 선택, 더블클릭 동종 전체 선택 |
| 지정 | 드래그 사각형으로 명령을 **예약**한다(채굴·수확·건설 청사진) — 폰이 나중에 와서 수행 |
| 건설 | Architect 메뉴 → 카테고리 → 항목 → 드래그. 청사진이 깔리고 **건설 노동은 폰이 한다** |
| 우선순위 | Work 탭 — 폰 × 작업종류 매트릭스. 체크박스 모드 / 수동 숫자(1~4) 모드 |
| 카메라 | WASD·화살표·화면 가장자리 팬 + 휠 줌 + 중클릭 드래그 |

### 1-2. UI 배치 — 화면 지도

```
┌─────────────────────────────────────────────────────┐
│  콜로니스트 바(상단) — 폰 초상 나열, 클릭=점프       │
│                                          [봉투 스택] │ ← letters: 사건 도착
│                                                     │
│                 (맵 = 화면 전체)                     │
│                                          [상시 경고] │ ← alerts: 식량 부족 등
│ ┌──────────────┐                                    │
│ │ 인스펙트 패널 │                                    │
│ │ (선택 대상)   │   [하단 바: Architect·Work·…탭]    │
│ └──────────────┘                  [시간 컨트롤(우하)] │
└─────────────────────────────────────────────────────┘
```

- **맵이 화면 전체이고 UI는 전부 그 위에 뜬 오버레이**다 — 우리가 이미 채택한 구조(#134 계열).
- **알림이 두 종으로 갈린다**: **letters**(봉투 — 사건이 *도착*했다, 우측 상단에 쌓임, 클릭해 읽음) / **alerts**(상시 조건 경고 — "식량 부족", 조건이 해소될 때까지 떠 있음). 이 구분이 중요하다 — *한 번 일어난 일*과 *지금도 문제인 것*은 다른 표면을 받는다.
- **인스펙트 패널** — 무엇을 클릭해도 좌하단에 그것의 정보가 뜬다. 폰이면 초상·현재 작업 문장("사냥하러 가는 중")·욕구 바·특성 탭. **게임의 서사는 대부분 이 패널에서 읽힌다.**
- 하단 바는 기능 탭(Architect·Work·Schedule·Assign·Research·History·…) — 우리의 좌측 패널 카테고리(#142)와 같은 계보.

### 1-3. 게임 흐름 — 리듬

```
시나리오 선택 → 스토리텔러·난이도 선택 → 착륙지 선택 → 폰 3인 확인 → 착륙
   → [초반] 생존 필수(침소·식량·전기)를 세운다
   → [중반] 확장 ↔ 위기 사건의 교대 — 스토리텔러가 "위협 → 휴지기 → 위협" 리듬을 관리
   → [장기] 목표(우주선 건조·왕실 승천)로 탈출 — 또는 전멸
   → 어느 쪽이든 엔딩 화면은 "이야기의 끝"으로 관대하게 마무리
```

- **스토리텔러가 게임 시작 전에 선택된다** — 카산드라(점증 리듬) / 피비(휴지기 김) / 랜디(순수 무작위). 사건의 *내용*이 아니라 *페이싱 성격*을 고르는 것.
- **위협 규모는 정착지의 부(wealth)·인구에 비례해 커진다** — 잘될수록 세게 맞는다(게임적 공정 장치).
- **위기 후 휴지기가 보장된다**(카산드라) — 연타로 죽이지 않는 것이 "이야기"를 만든다.

### 1-4. 서사 기계

- 폰마다 배경 스토리·특성 — 수치 효과와 서사가 결합돼 있다.
- 욕구 총합 = 무드 → 임계 밑이면 **정신 붕괴**(배회·폭식·은둔) — 상태 악화가 글리프가 아니라 **행동**으로 보인다.
- 죽은 폰은 무덤·추모로 남고, History 탭에 부·인구 그래프와 사건 로그가 쌓인다.
- 예술품에 정착지의 실제 사건이 새겨진다 — 게임이 스스로의 역사를 인용한다.

## 3. 채택 상세

### 3-1. 인스펙트 — 폰을 클릭하면 그 사람이 나온다 (P1 · 최우선)

**지금의 구멍**: 특성·사연(`traits.ts`)이 코드에 있는데 노출 표면이 **사직 편지와 인사 패널뿐**이다. 맵 위를 걸어다니는 폰을 클릭해도 아무 일도 일어나지 않는다 — 림월드에서 서사의 대부분이 읽히는 자리(인스펙트)가 우리에겐 없다.

**왜 P1인가 — 메시지 렌즈 1번의 최대 미수확 지점**: 사직 편지의 무게는 *미리 알던 사람*일 때 생긴다. 지금은 편지가 처음 보는 이름으로 온다. 플레이 중에 「김서준 · 내과 · 일중독 — 쉬는 법을 배운 적이 없다 · 오늘 9건째」를 클릭해 본 플레이어에게만, 주말의 편지가 **통계가 아니라 사람**이 된다. 환자도 같다 — 클릭하면 「내과 진료 대기 · 47분째」가 뜨는 순간, 회차·이탈 집계의 한 줄이 걸어다니는 개인으로 바뀐다. **"13곳 중 하나를 세운다"의 반대편을 익명에서 꺼내는 장치다.**

**추출 형태**(구현 설계는 후속): 폰 좌클릭 → 좌하단 카드. 의사 = 이름·과·특성 2+사연·피로/허기 수치·오늘 진료 수·**현재 작업 문장**("진료 중 — 3번째 환자" / "식당으로 가는 중"). 환자 = 원하는 과·대기 시간·응급 여부. 닫기는 ESC나 빈 타일 클릭. **건설 도구를 든 동안은 클릭이 건설이므로**, 선택은 도구 없음 상태의 좌클릭에만 얹는다(지금 그 클릭은 팬 시작과 안내 토스트뿐이라 충돌이 작다 — 클릭과 드래그의 분리 판정이 필요하며 이는 설계 단계 몫).

### 3-2. alerts — 상시 경고를 스택으로 (P1)

**지금의 구멍**: `setupWarningText`가 상태줄 **한 줄**에 하나만 말한다. "의자 없는 진료 책상 2개"와 "병상이 없어 응급을 못 받습니다"가 동시에 참이면 하나는 침묵한다. 림월드의 alerts는 **조건이 참인 동안 전부, 등급색으로** 떠 있다.

**추출 형태**: 우측 가장자리(줌 버튼 아래) 세로 스택. 후보 경고는 전부 기존 판정식의 재노출이다 — 새 규칙을 만들지 않는다: ① 진료실·의사 없음(개원 전) ② 의자 없는 진료 책상 N ③ 병상 0(응급 수용 불가) ④ 대기실 좌석 0 ⑤ 피로 위험(80+) 의사 N ⑥ 식당 없음 + 굶는 의사. 색은 관례대로 **위험=적 / 주의=황**, 그리고 색 단독 신호 금지 규칙(기존 관통 규칙)에 따라 텍스트가 항상 붙는다. 메시지 정합: 경고는 "네가 뭘 잘못했다"가 아니라 **"구조에 지금 구멍이 있다"**를 말하는 자리다 — 문구를 그 방향으로 쓴다(기존 `setupWarningText` 문구 계승).

### 3-3. 키보드 최소셋 (P1 · 소품)

스페이스 = 일시정지 토글, ESC = 도구·패널·선택 해제. **"마우스 클릭·드래그만으로 완주"는 제출 문서의 계약이라 유지**하고, 키보드는 가속 수단으로만 얹는다. 1·2·3 배속키는 ⏸ — 스페이스만으로 림월드 손맛의 8할이 온다(위기 순간의 반사적 정지).

### 3-4. 의사 바 — 상단 초상 열 (P2)

인원이 화면 밖(다른 방·팬 밖)에 있으면 피로 머리 위 바가 안 보인다. 의사는 한 판에 최대 열 명 남짓(전국 풀 총 18)이라 상단 바에 초상+피로 미니바가 실현 가능하다. 클릭 = 카메라 점프 + 인스펙트(§3-1과 결합). **떠난 의사 자리를 빈 칸으로 남기는 변형**을 검토할 것 — 림월드에는 없는 우리 고유의 한 수로, "풀은 줄기만 한다"가 상단 바에서 상시 보이게 된다(빈 초상 = 돌아오지 않는 사람).

### 3-5. 위기 후 휴지기 — 이벤트 리듬 규칙 (P2)

림월드 스토리텔러의 핵심은 사건 선택이 아니라 **리듬**이다(위협 → 휴지 → 위협). 우리 이벤트 엔진에는 불공정 조합 가드(병상 0 + 대량 응급 차단)는 있지만 **연속성 가드**가 없다 — 대형 사건(대량 응급·전염병) 다음날 또 대형 사건이 올 수 있다. "대형 사건 다음 날은 대형 사건 후보에서 제외" 한 줄이면 된다. LLM 디렉터에게도 같은 제약을 프롬프트가 아니라 **후보 목록 축소**로 강제한다(판정은 코드, 연출은 LLM — 2콜 원칙 그대로).

### 3-6. 스토리텔러 선택 화면 (⏸ 본선 후보)

림월드는 시작 전에 서사의 성격을 고르게 한다. 우리판: 시작 화면에서 「AI 스토리텔러(키 있음) / 기본 서사(결정론)」를 **명시적으로 고르는** 한 장 — 지금은 배지로 사후 고지만 한다. 심사위원이 "AI를 빼면 무너지는가"를 **시작 화면에서부터** 자문하게 만드는 어필 장치. 다만 새 화면 하나 = 마감 리스크라 본선으로 미룬다.

## 4. 기각 상세 — 왜 안 가져오는가

### 4-1. 드래프트(직접 통제) — 메시지 붕괴의 최단 경로

림월드의 직접 통제 예외는 전투를 성립시키는 장치다. 우리가 이것을 들이면 — 응급이 회차되는 순간 플레이어가 의사를 집어 문 앞으로 끌고 갈 수 있으면 — **"내가 직접 뛰었으면 살렸다"가 성립한다.** 그 순간 나쁜 결과의 원인이 구조에서 플레이어의 조작 실력으로 옮겨가고, 게임 전체가 "정답 있는 퍼즐"로 뒤집힌다(엔딩 철학이 기각한 바로 그 프레임). **간접 통제는 우리 게임에서 불가침이다** — 림월드에서는 재미의 선택지였던 것이 우리에게는 논지다.

### 4-2. 부(wealth) 비례 위협 — 인과가 어긋난다

림월드는 잘될수록 세게 맞는다 — 도전의 공정성을 위한 게임적 장치다. 우리가 이식하면 "병원이 성장해서 벌을 받는다"는 인과가 생기는데, 우리 압력의 출처는 **성장이 아니라 구조 상수**여야 한다(수가·고정비·풀 고갈 — 처음부터 거기 있었고 플레이와 무관하게 그대로인 것). 스토리텔러가 "구조적 약점을 찌르는" 것(빈 병동에 대량 응급)은 유지하되, **위협의 크기가 플레이어의 성과를 따라 커지는 스케일링은 들이지 않는다.** 잘한 플레이어와 못한 플레이어가 같은 구조를 겪고 같은 종류의 결말에 닿는 것 — 그것이 우리 논지다.

### 4-3. 연구 트리·성장 해금

"연구하면 더 나은 수단이 열린다"는 림월드 장기 루프의 축이지만, 우리 판의 핵심은 **12주 유한 + 구조 불변**이다. 판 안에서 구조를 개선할 수단이 생기는 순간 "왜 그걸 더 빨리 안 찍었나"가 실패의 원인이 된다 — 개인 귀책의 부활. 기각.
