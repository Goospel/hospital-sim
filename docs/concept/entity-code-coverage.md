# 엔티티 → 게임 코드 반영도 (구현 커버리지 스냅샷)

> **목적**: [domain-entities.md](domain-entities.md) 카탈로그(105) + [nursing-entities.md](nursing-entities.md) 증보(간호 축)의 도메인 엔티티가 **현재 게임 코드(`src/`)에 얼마나 구현됐는지** 대조한 스냅샷. 카탈로그가 "무엇을 모델링하기로 했나"라면, 이 문서는 "그중 무엇이 실제로 코드로 굳었나"다.

## 두 코드 축 — 판정 전에 읽을 것

| 축 | 경로 | 라우트 | 성격 |
|---|---|---|---|
| **sim** | `src/sim` + `src/components/Sim*` | `/` (메인) | 리얼타임 타일 경영 — 12주 생존, 폰(의사·간호사·환자), 피로·사직, 지역 4타입, 간호등급, 소송 위축 |
| **classic** | `src/game` | `/classic` | 전원 콜 수용/거절 판정 — STEMI 한 주, 배후진료 게이트, 골든타임, 신문 |

판정은 **두 축 합집합**으로 했다(어느 쪽이든 구현이면 ✅) — 단 표의 「축」 열이 어디에 사는지 밝힌다. **sim만 보면 커버리지는 이 표보다 낮다**: 흉부외과·당직·야간·골든타임·신문·진료과 가산·비급여 구분은 classic 전용이다.

## 검증이 잡은 주목할 점

- **구 ✅의 상당수는 classic에만 산다** — 흉부외과(과·전문의)·당직·야간·골든타임·신문·진료과 가산·정책수가 패키지·비급여 구분·PCI 병원 목록. sim은 이들을 의도적으로 잘랐거나(흉부 "2주차 절단") 다른 기계로 대체했다(신문→이벤트 연출문). **제출 빌드(메인 `/`)만 기준으로 삼으면 이 행들은 ✅가 아니다.**
- **sim의 신설 축은 카탈로그 밖에서 왔다** — 수납 창구·책상(정원)·피로·지역 4타입·소송 위축은 간호 증보와 게임 파생에서 온 것으로, 본 카탈로그 105에는 대응 행이 없거나 부분 대응이다. 카탈로그가 코드를 못 따라가는 방향의 드리프트가 시작됐다.
- **간호 축은 N1·N2 고리만 선택 구현** — 「인력→등급→수가」(간호등급제·가감산·인건비)와 「소진→이탈→더 나쁜 배치」(신규 임계 절반·재채용 악순환)는 상태전이+경제로 완전 구현. 「PA 권한 이동」(N3) 축은 행위자·제도·자원·사건 전부 0건 — nursing-entities.md의 "적용 순서는 사용자 결정"이 코드에 그대로 반영된 형태다.
- **방어진료가 인과로 연결됐다** — 구 스냅샷은 "소송회피→검사 인과 미연결"이라 ⬜였는데, 지금은 소송이 특정 의사의 응급 우선순위를 실제로 내린다(`events.ts:221-235`). 위축의 방향이 '과잉 검사'가 아니라 '응급 회피'로 구현된 점이 카탈로그 정의와 다른 각색.
- **강등 2건은 코드 후퇴가 아니라 판정 엄격화** — 업무상과실치사상(🟡→⬜)·카테터실(🟡→⬜)은 "주석·docstring만 남으면 ⬜" 규칙을 일관 적용한 결과다.
- **채용 예산 100억은 낡은 수치** — 카탈로그·구 스냅샷의 「채용 예산(100억)」은 현재 5억(`SETUP_BUDGET_MANWON = 50_000`). 카탈로그 갱신 후보.
- **취약지 데이터는 있는데 화면에 없다** — `koreaMap.ts`의 응급의료취약지 17곳 지정표는 고시 대조 테스트로 잠겨 있으나 렌더 경로가 없다(표시도 규칙도 아님). 살릴지 지울지 결정 후보.

## 함의

직전 스냅샷의 결론("카탈로그는 청사진이고 핵심 병목만 굳었다")은 유지되되, 두 가지가 달라졌다. 첫째, **성장의 방향이 카탈로그 바깥이었다** — 134커밋의 대부분(타일 경영·폰·피로·지역·간호)은 본 카탈로그 105개가 아니라 간호 증보와 게임 파생 엔티티를 구현했다. ⬜ 51→37의 개선분도 절반은 플레이버 승격(⬜→🟡)이지 기계화(✅)가 아니다. 둘째, **"게임에 있다"의 기준이 갈라졌다** — 제출 빌드는 sim인데 커버리지의 뼈대(골든타임·신문·정책 이벤트)는 classic에 있다. 다음 확장에서 "카탈로그의 ⬜를 채울까, classic의 ✅를 sim으로 이식할까"는 서로 다른 작업이며, 이 표의 「축」 열이 그 구분의 단일 출처다.
