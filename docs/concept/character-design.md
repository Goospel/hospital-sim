# 캐릭터 디자인 — 의사 · 환자

> **목적**: 세션이 끊기고 새로 시작해도 같은 캐릭터가 나오게 한다.
> 이 문서를 읽는 사람은 대개 **다음 세션의 나(Claude)**다 — 캐릭터를 만지기 전에 여기부터 본다.
> 관련: [game-concept.md](game-concept.md) · [domain-entities.md](domain-entities.md)

## 0. 경계 — 값은 코드에, 이유는 여기에

**색 코드·픽셀 격자·크기 값을 이 문서에 복붙하지 않는다.** 그 순간 한쪽이 조용히 낡는다(CLAUDE.md가 세 번 경고한 이중 기재 병).

| 무엇 | 단일 출처 |
|---|---|
| 스프라이트 벡터 좌표·팔레트·과별 색 | `src/components/PixelSprite.tsx` |
| 표시 크기·배치·조명 워시(옛 판 `/classic`) | `src/components/HospitalMap.tsx` |
| 타일 맵의 방·벽 색과 **조명·AO 계수**(본편 `/`) | `src/components/TileMap.tsx` (`ROOM_STYLE`·`SHADE`·`shade`) |
| 부지 밖 배경 팔레트·발광 | `src/components/Backdrop.tsx` (`BACKDROP_PALETTE`) |
| 배회·보행 애니메이션 | `src/app/globals.css` (`hm-wander` · `hm-walk` · `hm-walk-rev`) |
| 아바타의 존재·위치 규칙(파생) | `src/game/hospitalMap.ts` (`deriveMapScene` — 게임 중 · `deriveSetupScene` — 개원 전) |

**이 문서가 유일한 출처인 것**: 아래 §1~§6 — 원칙 · 금지 · 추가 절차. 코드는 "무엇"만 말하고 "왜 그렇게만 하는가"는 안 적혀 있다.

## 1. 공통 형식 (의사·환자 공유)

- **해상도 독립 벡터를 inline SVG로 그린다.** 이미지 파일 0개 → 번들 영향 0, 정적 export(GitHub Pages) 안전.
  - ⚠️ **2026-07-30까지는 8×8 픽셀 그리드(`<rect>` 한 칸씩)였다.** 바꾼 이유: 16px 타일에서 형태가 뭉개져 사람과 집기가 같은 회색 덩어리로 보였다 — 화면이 "옛날 테트리스"로 읽히던 원인의 절반이 여기였다(나머지 절반은 휘도 대역 — `TileMap.tsx` 주석·[T-115](../../claude-docs/troubleshooting/T-115.md)). **파일 경로는 그대로 `PixelSprite.tsx`다**(import 3곳과 이 문서의 §0 표가 그 경로를 든다).
  - ⚠️ **SVG 그라디언트를 쓰지 않는다 — 계약이다.** 인라인 SVG가 폰마다 한 벌씩 렌더되므로 `<linearGradient id>`를 쓰면 문서 안에 같은 id가 수십 개 생기고, 첫 요소가 언마운트될 때(환자 퇴원) 나머지의 fill 참조가 어디로 붙는지가 브라우저 구현에 달린다. 대신 **평면 2~3단 셰이딩 램프**로 입체를 만든다.
- **외부 스프라이트·타일셋을 추출해 쓰지 않는다.** ZEP·상용 에셋 모두. 대회 제출물이라 실제 저작권 리스크다. 참조하는 것은 **형식**(2D 탑다운)까지이고, 이는 Gather.town·스타듀밸리·테마 호스피탈이 공유하는 장르 관습이다.
- **실루엣은 하나(`Figure`)를 공유하고 팔레트만 다르다.** 벡터로 옮긴 뒤에는 형태를 나눌 *수* 있게 됐지만 **그대로 둔다** — 의사와 환자가 같은 몸을 쓰는 건 이 게임 주제이기 때문이다: 다른 종족이 아니라 **같은 사람이 어느 자리에 있느냐**의 문제다. (옛 근거였던 "8×8에서 형태를 나누면 뭉개진다"는 이제 성립하지 않으므로, 남는 근거는 주제 하나다.)
- **인물만 3/4 시점이고 집기·바닥은 탑다운이다**(2026-07-31). 정탑다운에서는 **옷이 원래 안 보인다** — 위에서 내려다보면 어깨와 정수리만 보이는데 옷의 정보는 전부 앞면에 있어 그 면이 화면을 안 향한다. 그래서 무엇을 그려도 "어깨에 얹은 무늬"가 되고, 시안 판정이 *"흰 가운을 입은 것 같지가 않고 그냥 색만 2개 섞은 느낌"*이었다. 시점을 섞는 것은 비용이 아니라 **이득**이다 — 사람만 기울어 있어 집기·바닥과 저절로 갈린다. 예외 하나는 §3의 누운 환자다.
- **역할 구분은 색으로만 한다.** 아이콘·배지·말풍선·이름표를 얹지 않는다.
- **머리에 점을 찍지 않는다.** 구면감을 내려고 왼위에 하이라이트 원을 뒀더니 어두운 머리카락 위의 흰 점이 **눈 하나**로 읽혔다(160px로 띄워 실측, 2026-07-30). 표정·얼굴 특징 금지는 §2·§3의 규칙이고 **우연한 눈도 위반**이다.

## 2. 의사

- **흰 가운 + 과 색 수술복.** 과 색은 **가슴(수술복 몸통)과 소매 커프스 두 곳**에 나온다 — 3/4로 옮기며 어깨에서 내려왔다. 한 곳만 있으면 무늬로 읽히고, 두 곳에 있어야 "가운 안에 다른 옷을 입었다"는 레이어로 읽힌다.
  - **과 색 팔레트 규칙: 8과 전부 채도 있는 수술복 톤이다**(채널 폭 ≥ 25 — `pixelSprite.test.ts`가 잠근다). ⚠️ **2026-07-31까지의 규칙 "수익과는 무채색 회색"은 폐지됐다**(미용 `#a1a1aa`·검진 `#71717a` → 금 `#c8a34a`·녹 `#4a7f5a`). 대조 장치로서는 좋았지만 화면에서 안 굴러갔다: 무채색은 색상 단서가 없어 **휘도로만** 싸워야 하는데 그 축은 유채색 6과가 이미 점유했고, 회색 둘은 서로도 환자 회색과도 안 갈렸다. 「돈이 되는 과」를 색으로 묶는 더 강한 안은 톤 가드레일(개인이 아니라 구조를 겨눈다)과 어긋나 기각했다 — **수익과를 지목하는 일은 색이 아니라 장부가 한다.**
- **상태는 배지가 아니라 밝기 + 방 안 환자.** 진료 중이면 가운이 밝아지고 진료대에 환자가 눕는다. 한가하면 가운이 어둡고 진료대가 빈다. 상태점·아이콘을 새로 붙이지 않는다.
- **의사는 항상 자기 진료실 안에 있다**(2026-07-24 개편). 예전엔 한가한 의사가 복도로 나와 환자와 나란히 줄 서 보였는데, 그게 "누가 의사고 누가 환자인지"를 흐렸다 — 복도 zone을 없앴다. 이제 진료 여부는 위치가 아니라 **가운 밝기·진료대 환자 유무**가 말한다. 단 예외 하나: 한가한데 방이 소등되면(야간·수익과) 퇴근해 사라진다 — 진료가 남았으면 소등돼도 끝날 때까지 지킨다. `deriveMapScene`이 `busyUntil` 하나에서 파생하므로 표시용 상태를 따로 만들지 않는다.
- **이름은 결정론 한글 이름**(`doctorName`, RNG 0). 같은 선택은 항상 같은 명단이다.
- **성격·사연·감정 서사는 없다.** 의사는 개인이 아니라 **자리 하나**다. "번아웃한 순환기 김 선생의 사연"을 넣는 순간 시스템 이야기가 인물 드라마가 된다.
  - **2026-07-24 부분 해제(사용자 결정, [채용 데스크 스펙](../superpowers/specs/2026-07-24-hiring-desk-setup-design.md))**: 픽셀 초상(FIGURE 확대 + 머리·피부 변주)·기계적 약력(연차·근무처)·요구 계약금·티어 파생 진료 속도는 **허용** — 자리의 스펙 시트이지 인물 소개가 아니다. 성격·감정·사연·대사는 계속 금지.
- 유일한 개체 단위 상태 표현은 담당 수와 피로 막대(`DoctorRoster`)이고, 그것도 숫자·막대뿐 해석 문구가 없다.

## 3. 환자

- **익명 회색. 이름도 나이도 성별도 사연도 없다.** 도메인 타입 `Patient`가 갖는 건 `requiredSpecialty`와 `severity`뿐이다.
- **이것은 의도적 영구 보류다.** 개인 서사가 붙으면 "**시스템이** 문제"가 "**이 환자가** 안됐다"로 미끄러진다. 플레이어를 울리는 게 목적이 아니라 구조를 보게 하는 게 목적이다.
- **환자는 말하지 않는다.** 목소리를 내는 건 환자가 아니라 **전화 건 쪽(다른 병원 담당자)**이다(`CALLER_PLEA`). 톤은 명랑한 시스템 대사와 인간의 대가 사이의 낙차이고, **과녁은 시스템의 태연함이지 환자도 거절하는 의사도 아니다.**
- **환자 동선: 입구 → 대기실 의자 → 진료실**(2026-07-24). 도착한 환자는 대기실(건물 좌하단) 의자에 앉아 기다리고, 차례가 되면 진료실로 옮겨 **진료대(그 과 방의 slot 0)**에 눕는다. 같은 과 둘째 환자부터는 **병동 침대**(우하단), 병동까지 차면 방 안에 서서 받는다 — 환자는 상한 없이 어딘가엔 반드시 보인다.
- **누운 환자는 §1 3/4의 유일한 예외다 — 탑다운으로 그린다**(`LyingPatientSprite`, 2026-07-31). 서 있는 3/4 인물을 90° 돌리면 "누운 사람"이 아니라 **"옆으로 넘어진 사람"**이 된다(3/4는 몸통 앞면이 카메라를 향하는 포즈라 돌리면 그 면이 옆을 본다). 서 있는 환자와 누운 환자가 다른 그림체가 되는 것은 **의도적 수용**이다 — 자세마다 3/4 포즈를 새로 그리면 그림이 인물 종류 × 자세로 불어난다.
- **화면에 나오는 회색 인물은 두 종류이고 섞으면 안 된다**:
  - **진료 중·대기 환자** — 게임 상태(`busyUntil`·대기 큐) 파생. 진료 중인 의사 1명 = 환자 1명. **병원 건물 안**(진료대·병동·대기실 의자)에만 있다.
  - **배경 보행자** — 순수 장식. 게임 상태가 아니고(`MapScene` 밖), **병원 밖 거리 밴드**에서만 지나간다(외벽으로 안과 갈려 "지나가는 사람"이 명확하다). 불투명도를 낮추고 `aria-hidden`이다. 이걸 `avatars`에 섞으면 「보이는 것 = 게임이 모델링하는 것」이 깨진다.

## 4. 움직임

- **세 층이 서로 다른 CSS 속성을 쓴다** — 겹치면 아바타가 튄다:
  - 배치 이동(대기실↔진료실↔병동): 바깥 div의 `left`/`top` + transition
  - 유휴 배회: 안쪽 div의 `transform`
  - 배경 보행: `left` 키프레임(별도 레이어, 좌·우 두 방향 `hm-walk`/`hm-walk-rev`)
- **좌표는 건물 내부 %다.** 가구(의자·침대·진료대)와 아바타가 같은 좌표 함수(`chairPos`·`bedPos`·`examBedPos`…)를 공유해 사람이 집기 위에 정확히 겹친다 — 한쪽만 옮기면 어긋나므로 좌표는 `HospitalMap.tsx` 한 곳에서만 정한다.
- **아바타마다 박자가 다르다**(`wanderTiming`). 전원이 같은 주기로 흔들리면 사람이 아니라 기계로 보인다. 박자도 id 해시 파생이라 결정론이다(RNG 0 원칙은 표시 레이어에도 적용된다).
- **연출 층은 게임 시계와 분리돼 있다.** 플레이어가 콜을 노려보느라 시계가 멈춰도 병원은 계속 돈다.
- **`prefers-reduced-motion`은 필수 경로다.** 배회는 정지, 배경 보행자는 통째로 숨김(애니메이션만 끄면 거리 왼쪽 끝에 겹쳐 선다).

## 5. 캐릭터를 손대기 전 체크리스트

1. **새 실루엣이 정말 필요한가** — `FIGURE` + 팔레트 교체로 안 되는가? (간호사·보호자·구급대원 전부 팔레트로 된다)
2. **값을 `PixelSprite.tsx` 밖에 쓰려는가** — 컴포넌트에 색을 하드코딩하지 않는다.
3. **개인 서사(이름·나이·표정·초상)를 붙이려는가** — §2·§3 위반. 하지 않는다.
4. **해석 문구를 붙이려는가** — "과로 상태입니다" 같은 카피 금지. 사실만 놓는다(메모 `game-show-dont-tell`).
5. **외부 에셋인가** — 금지(§1).
6. **새 상태를 배지로 표현하려는가** — 먼저 밝기·위치로 되는지 본다.
7. **게임 상태를 새로 만드는가** — 표시층은 파생만 한다. 판정·경제에 0 침습.
8. **reduced-motion에서 깨지지 않는가.**

## 6. 하지 않기로 한 것 (의도적 보류 — 새 세션이 되살리지 말 것)

| 안 하는 것 | 왜 |
|---|---|
| 환자 이름·나이·사연·초상 | 시스템 문제가 개인 신파로 미끄러진다(§3) |
| 의사 표정·감정 애니메이션 | 읽히면 인물 드라마가 된다(벡터로 옮긴 뒤에는 "안 읽힌다"가 근거가 아니라 **금지**만 남는다 — §1의 "머리에 점을 찍지 않는다") |
| 4방향 스프라이트·걷기 프레임 | 위치 변화만으로 충분하다. 프레임이 늘면 팔레트 규칙이 8배로 늘어난다 |
| 외부 에셋·AI 생성 이미지 | 저작권 리스크(제출물) + 코드로 그린 층과 톤 일관성이 깨진다. **2026-07-30 재확인**: 그래픽 격상 요구에 대해 이미지 에셋 대신 코드 상한(휘도 재배치·조명·벡터)으로 답했다 |
| 캐릭터 초상화·프로필 UI | ~~개체에 시선이 모이면 대조가 안 보인다~~ **2026-07-24 부분 해제**: SETUP 지원서의 픽셀 초상·기계적 약력만. 감정 표현·개인 사연·환자 개인화·대사는 금지 유지(§2·§3) |
| 환자 대사 | 환자는 말하지 않는다 — 목소리는 발신자 몫(§3) |
