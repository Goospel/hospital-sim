# 설계: 완전 림월드식 건설 — 자유 벽 · 영역 인식 · 용도 지정 · 가구 분리

> 사용자 결정(2026-07-28): *"림월드처럼 영역 선택과 벽·가구 배치를 분리하자"* — 절충안(가구만 분리)이 아니라 **완전 림월드식**을 선택했다.
> 촉발 문제: 진료실을 아무리 크게 지어도 의사 1명만 들어간다(가구 자동 배치가 책상 1개 고정 + 방 단위 배정) — 크기가 비용만 늘리는 함정.
> ⚠️ 마감(8/10) 리스크가 큰 재설계라 **PR 3개로 쪼개고, 매 PR에서 게임이 플레이 가능해야 한다**. 제출 영상·게임소개 스크린샷은 이 재설계 착지 후 기준으로 찍는다.

## 0. 무엇이 바뀌나 (플레이어 관점)

지금: 방 타입을 골라 사각형을 드래그하면 벽·문·가구가 한 번에 생긴다.
이후: **벽을 쌓고 → 문을 내고 → 둘러싸인 공간에 용도를 지정하고 → 가구를 놓는다.** 네 가지가 전부 별개 도구다.
진료실 수용량은 **책상 수**가 정한다 — 큰 방에 책상을 여럿 놓으면 의사도 여럿 들어간다(PR 3).

## 1. 코어 모델

### 1-1. SimWorld 필드

- **제거**: `rooms: Room[]` (선언형 사각 방 — PR 1에서는 어댑터로 유지, PR 2에서 제거)
- **추가**:
  - `walls: ReadonlySet<number>` — 벽 타일. 타일 인덱스는 path.ts의 기존 규약(`y * GRID_W + x`) 재사용.
  - `doors: ReadonlySet<number>` — 문 타일. **통행 가능**하되 영역 경계다.
  - `designations: ReadonlyArray<{ at: Pt; type: RoomType; dept?: SimDeptKey }>` — 용도 앵커. 배열 순서 = 지정 순서 = 충돌 시 우선순위(결정론).
- `Furniture`에서 `roomId` 제거 → `{ kind, x, y }`. 소속은 좌표가 말한다(영역 파생).
- 불변 취급: 편집 시 새 Set/배열로 교체(틱 순수성 계약 유지). 파생 계산의 순회는 **좌표 정렬 순서**로 명시해 Set 삽입 순서 의존을 없앤다.

### 1-2. 영역(Region) — 파생값, 저장하지 않는다

```
computeRegions(world): Region[]
Region { id: number(성분 내 최소 타일 인덱스 — 결정론적 대표),
         tiles: ReadonlySet<number>,
         doors: ReadonlySet<number>,   // 성분 경계에 인접한 문
         type?: RoomType, dept?: SimDeptKey }
```

- 영역 = 벽·문이 아닌 타일의 4방 연결 성분 중 **격자 가장자리에 닿지 않는 것**. 가장자리에 닿으면 마당(영역 아님).
- flood fill은 벽·문에서 멈춘다. 문은 어느 영역에도 속하지 않는다(경계 타일).
- 용도: `designations`를 순서대로 훑어 앵커 타일이 속한 영역에 type/dept를 부여한다.
  - 이미 type이 있는 영역의 두 번째 앵커는 **무시**(먼저 지정이 이김) — 상태줄이 "용도 충돌 — 벽으로 분리하세요"로 알린다.
  - 앵커가 벽 위·마당·문 위면 무효(경고). 벽을 허물어 영역이 병합/분리돼도 앵커는 좌표라 저절로 승계된다.
- 성능: 48×32=1,536타일 flood fill은 싸다. 틱당 다중 호출을 피하기 위해 **호출부가 1회 계산해 인자로 넘기는 형태**를 기본으로 하고, 모듈 메모이제이션은 실측로 병목일 때만 붙인다(성급한 캐시 금지).

### 1-3. 통행

`buildBlockedSet = walls ∪ 가구 타일`. 문은 통행 가능. 기존 `blockedPerimeter`(방 테두리 규칙)는 제거된다. 경로 A*는 무변.

## 2. 건설 도구 (UI — PR 2)

footer 1행의 방 타입 버튼을 **도구 팔레트**로 교체: `[벽] [문] [책상] [의자] [침대] [카운터] [용도] [철거]`

| 도구 | 조작 | 규칙 |
|---|---|---|
| 벽 | 드래그 사각형 → **테두리** 타일 설치. 1줄 드래그면 직선 벽 | 기존 벽·문·가구 타일은 건너뜀(부분 설치). 폰 위 설치 허용(기존 관용 — revalidate가 탈출시킴) |
| 문 | 벽 타일 클릭 → 문으로 전환 | 벽 아닌 타일 거부(토스트) |
| 가구 4종 | 클릭 = 1개, 드래그 사각형 = 유효 타일 전부(의자 다량용) | 벽·문·기존 가구 없는 타일. 마당에도 놓을 수 있으나 기능은 용도 영역 안에서만(경고가 잡는다) |
| 용도 | 실내 영역 클릭 → 용도 6종 선택(진료실이면 기존 과 선택 행 재사용) | 같은 영역 재지정 = 그 영역의 옛 앵커 교체. 마당 클릭 거부("둘러싸인 공간이 아닙니다") |
| 철거 | 클릭/드래그 — 벽·문·가구 제거 | 건설비 50% 환불(내림). 문을 철거하면 벽이 아니라 **빈 타일**이 된다 |

- 미리보기·드래그 중 일시정지·거부 토스트는 기존 기계(placeRoom 미리보기·paused 파생) 계승.
- **비용표(만원, 단일 상수 `BUILD_COST`)**: 벽 30 · 문 50 · 책상 100 · 의자 20 · 침대 300 · 카운터 100. 기존 "부지 타일당 50만원" 제거. 밸런스는 이 표 한 곳에서 튜닝.

## 3. 게임 규칙 매핑 (소비자 전환표)

| 기존 (rooms 기반) | 신규 (영역 기반) |
|---|---|
| 대기석: WAITING 방의 CHAIR 앞 타일 | type=WAITING **영역** 내 CHAIR — 스팟 규칙(spots.ts) 동일 |
| 진료: 방 1개 = 의사 1명 (방의 첫 DESK) | **진료 슬롯**(PR 3, §4) — 책상 수만큼 |
| 응급 침대: WARD 방의 BED | type=WARD 영역 내 BED |
| 휴게·식사: LOUNGE/CAFETERIA의 CHAIR | 동일 매핑(영역 type만 바뀜) |
| `insideRoom(rect)` | `region.tiles.has(idx)` |
| `doorTile(room)` 자동 문 | `doors` 명시 타일 (전용 함수 제거) |
| `furnitureSpot(w, roomId, kind)` | 영역 내 가구 열거 + 동일 스팟 규칙 |
| 스토리텔러 컨텍스트 `wards` 수 | type=WARD 영역 수 |
| 채용 스폰·ENTRANCE·경로 A* | 무변 |

`simHud.setupWarningText`도 영역 기준으로 갱신: "대기실이 없습니다"(WAITING 영역 0) · "진료실 없는 의사 N명"(그 과 EXAM 영역/슬롯 없음) 등 — 문구 계약은 테스트로 잠근다.

## 4. 진료 슬롯 — 책상 수 = 의사 수 (PR 3)

- **슬롯** = EXAM 영역 안의 (책상, 환자의자, 의사스팟) 삼중:
  - 환자의자: 책상의 4방 인접 CHAIR 중 DIRS 순서(위·우·아래·좌) 첫 번째. 이미 다른 책상에 짝지어진 의자는 제외 — 책상 열거는 furniture 배열 순서(= 설치 순서, 결정론).
  - 의사스팟: 책상 4방 인접 **통행** 타일 중 환자의자가 아닌 첫 타일(DIRS 순서). 없으면 슬롯 불성립.
  - 인접 의자가 없는 책상은 슬롯이 아니다 — "책상만 놓으면 안 되고 의자를 붙여야 한다"가 배치 인과로 드러난다.
- 의사 배정: `Pawn.roomId` → **`deskAt: Pt`로 대체**(점유의 단일 출처 — taken 판정은 다른 의사의 deskAt). 배정 시 deskAt 기록 + 의사스팟으로 경로. `roomId` 소비자 전부 전환.
- 환자 흐름: 기존 doctorId 기계 유지 — 배정된 의사의 슬롯 환자의자로 걷는다. 진료 성립 삼중 일치(환자 과 == 영역 과 == 의사 과)는 그대로.
- 글리프·경고 확장: 방 없는 의사 `?` 문구를 "빈 진료 책상이 없어 대기 중"으로 일반화.

## 5. PR 분할 — 매 단계 플레이 가능

1. **PR 1 · 코어 지형·영역 모델(스트랭글러)** — walls/doors/designations + computeRegions + 통행 전환 + 소비자(패스파인딩·환자·응급·욕구·스팟·HUD·TileMap 렌더) 영역 기반 전환. **placeRoom은 호환 어댑터로 유지**: 내부적으로 "벽 테두리 + 문 1 + 용도 앵커 + 기존 오토 가구"를 새 모델로 생성 — 화면·플레이·기존 테스트 대부분 무변. TileMap은 벽·문 타일 렌더로 전환(보이는 결과는 거의 동일).
2. **PR 2 · 건설 UI 분리** — 도구 팔레트 + 비용표 + 철거, placeRoom·오토 가구·MIN_ROOM·roomCostManwon 제거, 온보딩 문구 갱신("벽을 쌓고 → 문 → 용도 → 가구"). 이 시점 진료실은 아직 영역당 의사 1명(기존 규칙 유지).
3. **PR 3 · 진료 슬롯 다의사** — §4 전체 + deskAt 전환 + 경고·글리프.

## 7. 리스크와 퇴로

- **PR 1이 최대 리스크**(소비자 전환 광범위 — 테스트 1,090건의 상당수가 rooms 전제). 어댑터 전략이 파손을 흡수하지만, **8/1까지 PR 1이 착지하지 않으면**: PR 1·2를 접고 "기존 드래그 방 + 크기 비례 오토 책상 격자 + 다의사 슬롯"의 절충안으로 후퇴해 수용량 문제만 해결한다. 이 판단은 사용자와 상의한다.
- 문 없는 밀실: 영역은 인식되지만 경로가 없어 아무도 못 들어간다 — 버그가 아니라 각색(림월드와 동일). 상태줄 경고 후보("문이 없는 방") — PR 2에서 여유 있으면.
- 벽으로 기존 폰·동선 봉쇄: 기존 stranded 처리(재탐색·이탈)가 그대로 받는다.
