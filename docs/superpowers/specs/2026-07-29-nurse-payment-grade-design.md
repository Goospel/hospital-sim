# 간호사 축 1단계 — 수납 + 간호등급 가감산 설계

> **결정(사용자, 2026-07-29)**: 「최소(간호사+수납) + N1(간호등급)」만. N2(신규 이탈 가중)는 시간이 남으면, N3(PA 위임)는 **문서로만**.
> **근거**: [nursing-workforce-grounding.md](../../research/nursing-workforce-grounding.md)(수치·부호) · [nursing-entities.md](../../concept/nursing-entities.md)(엔티티 N1~N3).
> **발단**: 카운터·접수처가 순수 장식이었다 — 유일한 실효가 통행 방해(100만원 내고 장애물을 산다). `PatientStage 'PAYING'`은 pawn.ts:81이 "RECEPTION 경유 수납 흐름 자리"로 **예약해 둔 좌석**이고, 이 설계가 그 좌석을 채운다.
> **PR 분할**: PR ① 간호사 폰 + 수납(아래 §1~§5) → PR ② 간호등급 가감산(§6). 각각 단독 머지 가능.

---

## 0. 한 줄 요약

간호사를 뽑아 접수처 카운터에 앉히면 **그때부터 진료비가 걷힌다**(없으면 미수금으로 샌다). 주간 결산은 간호 인력 수를 등급으로 환산해 수가를 ±10% 가감산한다 — **제도가 사람을 돈으로 자동 번역한다**(엔티티 문제 N1).

## 1. 간호사 폰 (PR ①)

- `PawnKind = 'DOCTOR' | 'PATIENT' | 'NURSE'`. **`'DOCTOR'` 리터럴 31곳(9파일) 전수 훑기가 이 태스크의 실비용이다** — 각 지점에서 "의사만인가, 직원 전체인가"를 판정한다. 대부분은 의사만이 맞다(진료 배정·피로·사직·과 필터). 간호사가 합류해야 하는 곳: 아침 입장(`freshMorning`)·통행/충돌·렌더.
- 채용: `hireNurse(w)` — `hireDoctor` 패턴. id `nur-${nextId}`. 과 없음(`dept` 없음). HirePanel에 간호사 줄 추가(라벨 「간호사 · 수납 담당」·주급 표기). **스타팅 로스터 게이트는 의사만 센다(불변)** — 간호사는 체크리스트가 안내한다(§4).
- 주급 `NURSE_WEEKLY_COST_MANWON = 300` (`dept.ts` 카탈로그 밖 — 과가 아니다. 자리는 `week.ts` 또는 신설 `nursing.ts`). **눈금 근거는 대소다**: 미용 의사(800)의 절반 이하 — 리서치의 "간호사 인건비 ≪ 의사"(봉직의 3억 vs 간호사, 부호만 계승). 절대액은 실측 후 조정 가능.
- **이번 슬라이스에서 간호사는 피로·사직·욕구 기계에 안 들어간다**(⏸ N2). `fatigueOf`·`BREAKS`·사직 판정이 `kind === 'DOCTOR'`를 유지하는 것이 그 구현이다 — 우연이 아니라 계약이므로 테스트로 못박는다(간호사는 300분 뒤에도 `fatigue` 없음).

## 2. 수납 판정 — 단일 출처 (PR ①)

```
hasCashier(w): boolean
  = RECEPTION 영역 안에 COUNTER ≥ 1  그리고  간호사 폰 ≥ 1
```

- `patientFlow.ts`(또는 신설 `payment.ts` leaf — spots 패턴)에 순수 함수로. **판정을 이 한 곳에 모으는 것이 계약이다**(`blocksWalk`·`servesDept`와 같은 이유): 환자 흐름·경고·체크리스트·결산이 전부 이 함수를 본다.
- 간호사의 "도착 여부"는 판정에 안 넣는다(뽑혀 있으면 성립). 진료실은 의사 도착을 기다리지만 수납까지 그러면 대기 상태가 하나 더 생긴다 — 마감 12일 전에 그 복잡도는 안 산다. 화면상 간호사는 아침에 카운터로 걸어가므로 대부분의 시간 어긋남이 없다.

## 3. 환자 흐름 — 'PAYING' 예약석을 채운다 (PR ①)

- **외래**: `IN_EXAM` 종료 시점에 갈림 —
  - `hasCashier` 참: 수익을 **아직 계상하지 않고** `PAYING` 전이. 카운터 앞 타일(`standSpot` — 카운터는 `blocksWalk` 참이라 앞 타일이 맞다)로 경로. **도착한 분에 수익 계상**(현행 `day.ts:103` 계상 로직이 그 분으로 이동) 후 `LEAVING`.
  - 거짓: 수익 계상 없음. `stats.unpaidManwon += 수가` 누적 후 곧장 `LEAVING`.
- **응급**: 판정만 공유하고 **이동은 없다**(처치 종료 시점에 `hasCashier`면 현행대로 계상, 아니면 unpaid). 침대에서 카운터까지 걷는 흐름은 응급의 서사(눕는다)와 어긋나고 emergency.ts 침습이 커진다.
- **19시 정산**: `PAYING`으로 걷는 중인 환자는 **수납 인정**(현행 "진행 진료 완료 인정"과 같은 계약 — 시계 모서리가 돈을 삼키면 안 된다). `settleDay`에서 처리.
- **간호사 아침 동선**: `freshMorning`에서 카운터 앞 타일로 경로(의사의 책상 배정 패턴). 카운터가 없거나 접수처 미지정이면 입구 근처 대기(의사의 "방 없음"과 같은 처지 — `doctorRoomlessMark` 유사 표시는 선택).
  - ✅ **구현 확정(2026-07-30, 설계 재가)**: `freshMorning` 분기가 아니라 **매분 도는 `assignNurseCounters`**(의사 책상 배정과 같은 자리)로 구현됐다. `freshMorning`이 모두의 경로를 비우므로 다음 분에 배정이 저절로 붙어 아침이 공짜로 커버되고, **낮에 뽑은 간호사가 그날 일한다** — 설계 원안보다 낫다. 부수 계약 변경 1건도 재가: `Σ byDept.patients == examsDone` 불변식은 수납 도입으로 **정산 뒤에만** 닫힌다(진료 완료와 수납이 다른 분이라 걷는 중인 환자가 잠시 벌어진다).
- 카운터 여러 개면 첫 번째(좌표 순 — `examSlots` 순회와 같은 규칙). 환자 줄서기(대기 행렬)는 **안 만든다** — 도착 즉시 결제라 겹침은 시각적 문제일 뿐이고, 좌석 증폭(#148에서 배운 것) 같은 시스템 왜곡이 없다.

## 4. 화면 (PR ①)

- **체크리스트 6번째 단계** (`setupSteps` 맨 뒤): label 「수납 창구를 만듭니다」 · hint 「[건설] > [카운터]를 놓고 [용도] > [접수처]로 지정, [사람] > [채용]에서 간호사를 뽑습니다. 창구가 없으면 진료해도 돈을 받지 못합니다.」 · done = `hasCashier(w)` · alert 「수납 창구가 없습니다 — 진료비를 받지 못합니다」.
- **ops 경고** `unpaid` (warn · `alertsOf`): 오늘 `unpaidManwon > 0`일 때 「진료비 N만원을 받지 못했습니다 — 접수처 카운터에 간호사가 없습니다」. **실제로 샌 뒤에만** 뜬다(#148의 `no-dept`와 같은 규칙). setup 체크리스트가 남아 있는 동안은 setup 경고가 먼저다(기존 섀도잉 유지).
- **하루 결산**: `DayRecord.unpaidManwon` 추가, 0보다 클 때만 「(못 받은 진료비 N)」 — `leftNoDept` 표기와 같은 형식.
- **렌더**: 간호사 스프라이트 = 의사 스프라이트 변형(팔레트 교체 — 흰 가운 대신 청록 계열). 인스펙트 카드: 이름·「수납 담당」·주급.
- **톤**: 미수는 플레이어 탓이라고 말하지 않는다 — 「받지 못했습니다」(상태)이지 「놓쳤습니다」(질책)가 아니다.

## 5. 회귀·테스트 계약 (PR ①)

- **TDD Red→Green**. 최소 커버: `hasCashier` 3분기 · 미수 계상 · PAYING 도착 계상 · 19시 걷는 중 인정 · 간호사가 피로/사직에 안 들어감 · 응급 미수 갈림.
- **경계 테스트**(#148 패턴): 접수처+카운터+간호사 완비 병원의 하루 수익 == 완료 진료 수가 합(걷는 시간이 돈을 잃게 하지 않는다) · `unpaidManwon === 0`.
- **회귀 픽스처 재핀 필요**: 표준 픽스처 병원에 접수처+카운터+간호사가 없으므로 수익이 0으로 떨어진다 → **픽스처에 수납 창구를 추가**하고 재핀(오늘 세 번째 — 머리말 각주 ③에 "왜"를 남긴다: 수납 없는 병원은 이제 표준이 아니다). `examsDone`·`pawnTiles`는 간호사 1명 추가분만 갈려야 정상.

## 6. 간호등급 가감산 (PR ②)

- **기준**: `NURSES_REQUIRED = ceil(의사 수 / 2)` (의사 0명이면 0). 근거는 정확한 제도 재현이 아니라 **번역**이다 — 실제 등급제는 병상당·환자수당 7단계지만 이 병원은 외래 중심이라, "진료 규모 대비 간호 인력"의 최소 형태로 옮긴다(리서치 §3 각색 고지 대상).
- **3단 판정** (`nurseGradeOf(w)` 순수 함수, 주간 결산 시점):
  - `BONUS`: 간호사 ≥ 필요 + 1 → 주간 진료 수익 **+10%**
  - `MET`: 간호사 == 필요 → 0
  - `SHORT`: 간호사 < 필요 → **−10%**
  - 상수 `NURSE_GRADE_RATE = 0.1` (가산·감산 대칭은 각색 — 실제는 가산 10~70%/감산 5~10% 비대칭. 화면 숫자는 밸런스, 비대칭 재현은 안 한다).
- **결산 형태**: `WeekSummary`에 `nursing: { count, required, grade, wageManwon, adjustManwon }` 블록. `netManwon = 수익 − 과별 고정비 − 간호사 주급 합 + adjustManwon`. **총액은 블록에서 유도**한다(byDept 유도 계약과 같은 이유 — 따로 합산하면 표와 총액이 갈린다). ⚠️ 간호사 주급 자체는 PR ①의 결산에 이미 들어가야 한다(공짜 노동 금지) — PR ①에서 `nursing.wageManwon`까지, PR ②에서 `grade`·`adjustManwon`을 얹는 순서.
- **주간 결산 UI**: 과별 표 아래 간호 줄 — 「간호 N명 (기준 M) · 주급 −X · 등급 가감 ±Y」. 감산 카피는 상태 서술만: 「간호 인력이 기준에 못 미쳐 수가가 감산되었습니다」(「당신」·「실패」 금지 — 톤 가드레일).
- **테스트**: 3단 경계(필요−1/필요/필요+1) · 의사 0 경계 · adjust 부호 불변식(SHORT면 음수·BONUS면 양수) · 유도 총액 == 표 합.

## 7. 범위 밖 (전부 ⏸ 기록 대상)

- **N3 PA 위임 토글** — **문서로만**(제출 기획 문서에 "봤고, 이렇게 설계할 수 있고, 톤 리스크와 일정 때문에 넣지 않았다"). 게임 코드 0줄.
- 수납 대기 행렬 · 간호사 도착 기반 수납 판정 · 등급 비대칭(가산 70%) 재현 · 야간간호료.
