# 설계 스펙 — 사직·이탈 (사람이 떠나면 장부가 좋아진다)

> **상태**: 확정 설계 (2026-07-25, brainstorming). 다음 = writing-plans → 구현.
> **맥락**: [피로 승격](2026-07-25-fatigue-adjudication-design.md)이 ⏸으로 남긴 후속 — *"피로 포화가 인력 제로섬([system.ts](../../../src/game/system.ts))과 만나는 다음 승격 후보"*. 피로는 지금 진료를 느리게 만들지만, 사람이 **떠나지는** 않는다. 그 마지막 고리를 잇는다.
> **주제**: 필수의료 이탈은 이 게임 소재의 심장이다. 저수가·소송·번아웃이 사람을 갈아 없애고, **그 자리는 돌아오지 않는다**([domain-entities](../../concept/domain-entities-detail.md): *"이탈은 표면, 배후 붕괴가 근본원인"*).

---

## 1. 목적 & 확정 결정

### 문제
피로가 100에 붙어 몇 주를 지나도 아무도 그만두지 않는다. 부하 → 피로 → 감속에서 사슬이 멈춰 있고, **사람이 소모품으로 소진되는 마지막 단계가 없다.**

### 확정 결정 (brainstorming 3-fork)

| # | 결정 | 채택 | 기각한 대안 |
|---|---|---|---|
| A | 사직 후 행방 | **필수의료를 떠난다** — 전국 풀에서 소멸, 재채용 불가 | 다른 병원으로 이직(풀 복귀 → 회전문 · "돈만 있으면 괜찮다"로 읽힌다) / 사유별 분기(개인 사연 금지선에 가장 가깝다) |
| B | 방아쇠 | **피로 포화 지속** — 단일 축 | 피로+소송(튜닝 면 확대) / 피로+1인 당직 기간(가속 조건 추가) |
| C | 발생 시점 | **주간 결산** — 다음 주부터 자리가 빈다 | 하루 마감 즉시(주 중 무대처로 붕괴) / 하루 판정+다음 주 공백(상태 하나 늘고 "통보됐는데 아직 일한다" 설명 필요) |

### 스코프 밖 (⏸ 의도적 보류)
- ⏸ 사직이 신문 기사가 되는 것 · 전 배후과 0명일 때의 별도 결말(폐업과 통합 여부) · 소송·저수가 방아쇠 축 · 사직 예고 UI · 해고(성장은 증축만 — 기존 계약).

## 2. 상태와 방아쇠

### 2-1. 포화 일수 카운터

```ts
export interface SessionState {
  // ... 기존 ...
  /** 유닛별 **피로 포화(FATIGUE_MAX)로 마감한 날 수**. 누적·주 간 유지, 리셋 없음. */
  saturatedDays: Record<string, number>
}
```

`completeReceiving`이 `stepFatigue` **직후 같은 자리**에서 스텝한다 — 그날 마감 피로가 `FATIGUE_MAX`면 +1, 아니면 그대로.

**리셋이 없는 이유**: ⓐ *"포화 상태로 일한 날은 회복해도 몸에 남는다"*가 정직하다 ⓑ 무엇보다 **완편 병원은 카운터가 영원히 0**이다 — 실측(피로 승격 §4-1)상 2인 분담은 최대 20, 수익과는 ≤1로 34조차 안 넘어 100에 닿을 길이 없다. 즉 이 카운터는 **구조적으로 망가진 배치에서만** 돌아간다. 리셋 규칙을 두면 "며칠 쉬게 해서 카운터를 되돌리는" 최적화 표면이 생기는데, 대응 레버가 채용뿐이라(피로 승격 결정 B) 그런 조작은 애초에 불가능하다.

### 2-2. 임계

```ts
export const RESIGN_SATURATED_DAYS = 4 // 예시값 — 아래 목표 곡선으로 튜닝
```

실측 곡선 대조(전부 수용, 순환기 1인): 1주차 포화 2일(D4·D5) → 2주차 3일 → **누적 5일로 2주차 결산에서 이탈**. 1주차에 대가를 배우고 2주차에 치르는 리듬이다. 응급을 더 거절하면 피로가 덜 올라 **시점이 미뤄진다** — 플레이어 선택이 실제로 움직인다.

### 2-3. 수익과 제외는 자동이다

미용·검진은 피로 무풍이라 카운터가 0이고, `POOL_INITIAL`은 애초에 배후과(`Specialty`)만 담는다. **별도 분기 없이** "떠나는 건 필수과뿐"이 나온다. 이 비대칭이 §5의 논지를 완성한다.

## 3. 판정과 파급

### 3-1. 판정은 `completeWeek` 한 자리

임계를 넘긴 유닛을 뽑아 세 곳을 함께 갱신한다(순수 함수 하나로 묶어 `session.ts`가 호출):

1. **명단의 단일 출처를 줄인다** — `choices.doctors[dept] −= 1`, `choices.hiredIds`에서 그 유닛의 `candidateId` 제거.
2. **세상에서 지운다** — `system.pool[그 과의 providesBackup] −= 1`. 되돌릴 수 없다(§1 결정 A).
3. **병원 재구성은 기존 경로가 한다** — 줄어든 `choices`가 GROWTH의 새 기준선이 되고, `canApplyGrowth`의 해고 방지 가드(`모든 과가 현재 이상`)가 자연히 그 위에서 작동한다.

### 3-2. ⚠️ 핵심 함정 — id 재번호로 생존자가 사직자의 피로를 상속한다

`Doctor.id`는 `doc-<dept>-<i>`로 **인덱스 기반**이다([doctor.ts](../../../src/game/doctor.ts) `materializeRoster`). 순환기 2인에서 1번이 사직하면 다음 주 명단은 `doc-CARDIOLOGY-1` 하나인데, **그건 예전 2번**이다. `fatigue`·`saturatedDays`가 id로 키를 잡으므로 **생존자가 사직자의 포화 상태를 그대로 물려받는다** — 방금 들어온 사람이 즉시 사직 임계에 걸릴 수 있다.

**교차 주 상태는 정확히 이 둘뿐이다**(확인): `busyUntil`·`busyWith`는 `initReceiving`이 하루마다 리셋하고 이월은 인접 하루 사이뿐이며, `beginWeek`은 이월을 빈 맵으로 연다. 그래서 리맵 대상은 `fatigue`·`saturatedDays` 두 맵으로 한정된다.

**해법 — 명시적 리맵**: 사직 처리 함수가 새 명단을 만든 뒤 **옛 유닛 → 새 유닛 대응**을 계산해 두 맵을 옮긴다.
- `candidateId`가 있으면 그것으로 매칭(지원자 출신은 고유하다).
- `candidateId`가 없는 무명 유닛은 **같은 과 안에서 무명끼리의 등장 순서**로 매칭(성장 중도 채용 경로).
- 대응이 없는 키(= 사직자)는 **버린다**.

> ⏸ **대안(보류)**: `Doctor`에 안정 식별자(`uid`)를 도입해 재번호 자체를 없애는 구조적 해법. `busyUntil`·`busyWith`·`log.assigneeId`·`hospitalMap`·`DoctorRoster`까지 파급이 커서 이번 슬라이스 밖이다. 리맵이 실전에서 취약하다고 드러나면 그쪽으로 승격한다.

### 3-3. 재채용은 기존 레버 그대로

다음 GROWTH에서 금고와 풀이 남아 있으면 채운다. **새 조작을 만들지 않는다** — 풀이 마르면 `canHire`가 이미 그 벽이고, 그때가 진짜 끝이다.

### 3-4. 도미노는 저절로 온다

자리가 비면 남은 사람이 그 부하를 받아(`pickAssignee`) 피로가 더 오르고 카운터가 더 빨리 찬다. **연쇄를 만드는 코드를 쓰지 않는다** — 기존 배정 로직의 결과다. 판정이 주간이라 도미노는 주를 건너 퍼진다(결정 C).

## 4. 표시 — 사실 한 줄

주간 결산(`WeekSummary`)에 사직 목록을 `과 라벨 · 이름 — 사직` 형태로 놓는다. **사유를 쓰지 않는다** — 피로 막대가 몇 주간 이미 말했고, 사유를 설명하는 순간 *"번아웃한 순환기 김 선생의 사연"*이 된다([character-design](../../concept/character-design.md) §43 금지선: *의사는 개인이 아니라 자리 하나*). 이름은 이미 명단에 있는 스펙 시트 수준의 정보다.

에필로그는 **새 문구 0** — 기존 `poolDepletion`(초기 → 잔여)이 사직분을 자동으로 반영한다.

## 5. 의도된 끔찍한 결과 — 사람이 떠나면 장부가 좋아진다

필수과 의사가 사라지면 ⓐ 그 과 고정비가 준다(`DEPARTMENTS`의 인당 고정비 × 인원) ⓑ 못 받는 응급이 늘어 **적자 콜이 줄어든다**. 그래서 **순이익이 오른다.**

**이건 버그가 아니라 이 게임이 하려는 말이다.** 공범 경로가 숫자로 보상받는 구조 — 사람을 갈아 없앤 결과가 장부에서 흑자로 나타난다.

⏱️ **시점 주의(구현 계약)**: 효과는 **사직한 그 주가 아니라 다음 주에** 나타난다. `completeWeek`은 이미 마감된 `ledgerDays`로 주간 순이익을 계산하므로 사직이 그 주 숫자를 바꾸지 않고, 고정비·처리량이 달라지는 건 병원이 재구성된 **다음 주**부터다. 그래서 결산 화면에서 나란히 놓이는 건 `이번 주 사직 1명`과 `다음 주 결산의 오른 흑자`이고, 플레이어는 **한 주를 건너 그 인과를 잇는다**. 둘을 잇는 해석 카피는 쓰지 않는다(show-don't-tell).

기존 경제 가드와 충돌하지 않는다: `[I8-a]`(전부 거절하면 적자)·`[I8-b]`(부문 손익 ≤ 0)는 이 방향과 무관하다.

## 6. 불변식 & 테스트 (TDD)

### 새 불변식
- **[R-0] 하위호환**: `saturatedDays`가 빈 맵이면 사직 0 → 승격 전과 완전히 동일.
- **[R-1] 수익과 면역**: 미용·검진만으로 7일을 완주해도 사직 0(피로 무풍의 귀결 — 실측으로 확인).
- **[R-2] 되돌릴 수 없음**: 사직은 `system.pool`을 줄이고, 어떤 경로로도 복구되지 않는다.
- **[R-3] 명단 정합**: 사직 후 `choices.doctors[dept]` = 그 과 `roster` 길이, `hiredIds`에 사직자 `candidateId` 없음.
- **[R-4] 상태 리맵**: 2인 중 1번이 사직하면 생존자(옛 2번)의 `fatigue`·`saturatedDays`가 **자기 값**을 유지하고 사직자 값을 물려받지 않는다. ← §3-2의 핀

### 기존 불변식 (전량 green 유지)
`[I8-a]`·`[I8-b]`·`[I3]`·「양심 경로는 적자」·`[I-A]`·`[I-B]`·`[F-0]`~`[F-2]`(피로 승격) · 폐업(`insolvencyStreak`) 흐름.

### 단위 테스트
| 대상 | 핀 고정할 계약 |
|---|---|
| 포화 카운터 스텝 | 마감 피로 = MAX면 +1 · 그 아래면 불변(리셋 아님) · 주 간 누적 |
| 사직 판정 | 임계 미달은 0명 · 임계 도달 유닛만 · 여러 명 동시 가능 |
| 사직 적용 | `choices`·`hiredIds`·`pool` 세 곳 동시 갱신 · 배후과 아닌 과는 `pool` 무변경 |
| 상태 리맵 | [R-4] · `candidateId` 매칭 · 무명 유닛 순서 매칭 · 사직자 키 제거 |
| 세션 흐름 | `completeWeek` → `WEEK_SUMMARY`에 사직 목록 · `nextWeek`·GROWTH가 줄어든 `choices`를 기준선으로 · 재채용은 풀이 남을 때만 |

### 실측 (브라우저)
순환기 1인 + 미용 3인으로 **3주 완주** — ① 1주차 결산 사직 0 ② 2주차 결산에 순환기 사직 1명 ③ 3주차 GROWTH에서 순환기 재채용 가능 여부(풀 잔여) 확인 ④ 재채용 **안 하고** 3주차를 돌리면 순환기 응급이 상시 하드락(`NO_BACKUP_CARE`) ⑤ **3주차 순이익이 2주차보다 오르는 것**(§5 — 사직 다음 주에 나타난다) ⑥ 생존 유닛이 없는 병원(순환기 0)에서도 콘솔 에러 0.

### 튜닝 계약
`RESIGN_SATURATED_DAYS`만 만진다(구조 불변). 목표: **1인 필수과는 2~3주차 이탈 · 2인 이상 분담·수익과는 무기한 잔류**. 울타리는 [R-1]과 I8 가드.

> 📌 **머지 통합 정정(2026-07-27)** — 이 설계는 사직분을 `system.ts`의 `releaseFromPool`(옛 `hireDelta`의 대칭)로 **풀에서 직접** 깎았다. 같은 날 병합된 지역 세계 시뮬(2026-07-26 spec)이 `SystemState.pool`을 `hirablePool(world.regions)`의 **파생값**으로 승격해, 풀을 직접 쓰는 함수는 불변식 `pool ≡ hirablePool(world.regions)`을 우회하는 **두 번째 쓰기 경로**가 됐다(그 spec §6이 같은 이유로 `hireDelta`·`backgroundAttrition`을 삭제했다).
>
> 그래서 차감을 `world.ts`의 `resignFromRegions(world, poolDelta, week)`로 옮기고 `completeWeek`이 `deriveSystem`으로 풀을 재파생한다. **가시 계약은 이 문서 그대로다** — 사직자는 재채용 불가(소멸)이고, `poolInitial`이 불변이라 에필로그의 "N → 잔여"가 사직분을 반영한다(실측 "전국 잔여 4→3"도 동일). 결정 A(사직 = 필수의료를 떠남)가 이제 **이름으로도** 드러난다: `hireFromRegions`는 이동, `resignFromRegions`는 소멸. 시드 salt는 채용(13)과 다른 축(23)이다 — 같은 주에 스트림을 공유하면 "그 주에 채용을 했느냐"가 사직자의 출신 지역을 바꾼다.

세부 단계는 writing-plans에서 확정한다.
