# 자유 영역 지정 — 벽·문 밀폐에서 해방 (림월드식)

> 2026-07-31 · 사용자 방향 지시: *"접수처는 대기실 바로 앞에 공개되어 있는데 여기에 문을 다는 건 어색해. 림월드도 영역은 건물이나 벽에 상관없이 지정하잖아. 이 게임도 그렇게 변경해."*

## §0 문제 — 밀폐 강제가 낳는 어색함

지금 영역은 **벽·문으로 둘러싸인 연결 성분**에만 생긴다(`regions.computeRegions` — 격자 가장자리에 닿으면 마당, 아니면 방). 용도는 앵커 좌표 하나가 그 성분에 입힌다. 그래서:

- **접수처에 문을 달아야 한다.** 현실의 접수 카운터는 대기실을 향해 열려 있는데, 이 게임은 닫힌 방이 아니면 `OUTDOORS`로 지정 자체를 거부한다.
- 개원 준비 체크리스트가 *"벽으로 사각형을 끌고 → 문으로 뚫고"* 를 모든 방의 전제로 가르친다 — 열린 공간이라는 선택지가 없다.

림월드의 영역(구역)은 건물·벽과 무관하게 플레이어가 칠한다. 이 게임도 그렇게 바꾼다.

## §1 확정 결정 (사용자 선택)

| # | 결정 | 선택지와 이유 |
|---|---|---|
| 1 | **드래그로 사각형 칠하기** | 용도(진료실이면 과까지)를 고르고 드래그하면 그 사각형이 영역이 된다. 벽 드래그와 같은 조작감. (하이브리드 — 밀폐면 한 클릭 — 는 "어디까지 지정될지"가 상황마다 달라 기각) |
| 2 | **나중 칠한 것이 이긴다** | 다른 용도 위에 칠하면 그 타일을 빼앗아 가고 기존 영역은 그만큼 준다. 재배치가 한 동작. (겹침 거부는 매번 두 단계라 기각) |
| 3 | **용도 목록에 「지정 해제」** | 드래그 범위의 지정만 지운다. 벽·가구는 그대로. 무료. (철거 도구 겸용은 벽·가구까지 같이 부서지는 오조작 위험으로 기각) |
| 4 | **A안 — 칠한 타일이 원천, 영역은 파생** | 아래 §2. (영역 객체 저장(B안)은 병합·분할 갱신을 잊는 자리 = 이중 기재라 기각) |

## §2 데이터 계약 — 칠한 타일이 원천, 영역은 여전히 파생

### SimWorld

```
- designations: ReadonlyArray<Designation>        // 삭제 (앵커 방식)
+ zones: ReadonlyMap<number, ZonePaint>           // 타일 인덱스 → 칠한 용도
```

`ZonePaint = { type: RoomType; dept?: SimDeptKey }` — `dept`는 `EXAM`에만 실린다(현행 `Designation`과 같은 규약). **불변 취급 계약 유지**: 편집은 새 Map으로 교체한다 — `computeRegions` memo와 TileMap 지형 memo의 키가 이 참조다.

### Region (regions.ts)

```
  id: number                     // 유지 — 성분 내 최소 타일 인덱스 (결정론적 대표)
  tiles: ReadonlySet<number>     // 유지 — 이제 "칠한 타일" 성분
- doors: ReadonlySet<number>     // 삭제 — 문은 더 이상 영역의 속성이 아니다
- type?: RoomType                // 필수로 승격:
+ type: RoomType                 //   칠한 타일에서만 성분이 나오므로 항상 있다
  dept?: SimDeptKey              // 유지
```

`type`이 필수가 되면 소비자의 `r.type === 'WARD'` 류 검사는 전부 그대로 참이고, `r.type &&` 방어는 죽은 코드가 되므로 걷어낸다. `doors`의 소비자는 테스트 둘과 체크리스트 `sealed` 판정뿐이다(§5에서 대체).

### computeRegions

**같은 (type·dept)로 칠해진 타일의 4방 연결 성분**이 영역이다. flood fill은 칠한 타일 위에서만 돈다(전 격자 1,536타일 → 칠한 수십~수백 타일). 밀폐 판정·가장자리 검사·문 수집이 전부 사라진다.

- 시그니처: `computeRegions(world: Pick<SimWorld, 'zones'>)` — memo 키가 `zones` 하나로 준다. **TileMap 지형 memo 키도 `walls`·`doors`·`zones` 셋으로 갱신**한다(벽·문은 여전히 지형을 그리므로 키에 남는다 — 영역 파생의 키가 아닐 뿐이다).
- id·순회 순서 결정론은 현행 유지(타일 인덱스 오름차순 → 결과가 id 오름차순).

### 파생이 공짜로 주는 것

- **병합**: 떨어진 두 조각을 이어 칠하면 성분이 저절로 하나가 된다.
- **분할**: 가운데를 「지정 해제」하면 저절로 둘이 된다 — 각자 새 id(최소 인덱스)로.
- **dept 분리**: 내과 진료실 옆에 외과 진료실을 벽 없이 붙여 칠해도 (type·dept)가 다르면 다른 영역이다.
- 떨어진 같은 용도 조각은 **서로 다른 영역**이다(진료실이면 슬롯도 각자).

## §3 규칙 변화 (build.ts)

### designateRegion → paintZone · eraseZone

```
paintZone(w, tiles: readonly Pt[], type: RoomType, dept?: SimDeptKey): PlaceResult
eraseZone(w, tiles: readonly Pt[]): PlaceResult
```

- `PlaceResult` 계약 유지 — 실패해도 `tiles`·`deltaManwon`이 실린다(미리보기가 같은 함수를 돌려 하이라이트를 그리는 현행 관례).
- **벽·문 타일은 자동 제외**(건너뜀 = `skipped`). 가구 타일은 칠해진다 — 가구는 영역 **안**에 있는 것이지 경계가 아니다.
- 이미 같은 (type·dept)인 타일도 건너뜀(`skipped`) — 대상 0이면 `NOTHING`.
- 다른 용도 타일은 덮어쓴다(§1-2). `eraseZone`은 칠해진 타일만 지운다(없으면 `skipped`).
- `EXAM`에 `dept` 필수(현행 throw 유지). EXAM이 아니면 dept를 떨군다(현행 유지).
- 비용 0(현행 유지 — `deltaManwon: 0`).
- **`OUTDOORS` 사유 삭제** — `BuildReason`에서 제거, simHud의 거부 문구(`둘러싸인 실내가 아닙니다`)도 함께.

### demolish

앵커 특례 주석(*"앵커는 건드리지 않는다"*)이 무의미해진다 — 철거는 벽·문·가구만 부수고 `zones`는 손대지 않는다(영역을 지우는 길은 「지정 해제」뿐). 벽을 부숴도 영역은 그대로다 — 옛 구조에서 벽이 뚫리면 방이 통째로 죽던 동작이 **사라지는 것 자체가 이 설계의 목적**이다.

## §4 화면 (TileMap · 건설 UI)

- **용도 도구**: 용도(+과) 선택 → 드래그 사각형 → `paintZone` 미리보기·확정. 「지정 해제」는 같은 줄의 마지막 항목. `BuildTool`의 `DESIGNATE`가 드래그형 도구로 바뀐다(현행은 클릭형).
- **바닥 색**: 칠한 타일에 `ROOM_STYLE[type].floor` — 현행과 같고, 산지만 바뀐다.
- **벽 색**: 현행 규칙(4방 먼저·대각 폴백으로 이웃 영역의 wall 색을 빌림) 유지 — 이웃 판정의 원천이 "성분 타일"에서 "칠한 타일"로 바뀔 뿐 알고리즘은 그대로다. 어느 영역도 안 닿은 벽은 중립색(현행).
- **조명(SHADE) 중심·반경**: 영역 타일 평균에서 파생하는 현행 식 그대로 — 산지만 바뀐다.
- **영역 오버레이(▦)**: 칠한 타일에 방 색·이름표(현행 유지). 열린 영역은 바닥 색 경계가 곧 시각 경계다 — 테두리 선 등 새 시각 장치는 이번 범위에 없다(써 보고 부족하면 후속).

## §5 개원 준비 체크리스트 (simHud.setupSteps)

| 단계 | 현행 | 변경 |
|---|---|---|
| 대기실 hint | *"[벽]으로 사각형을 끌고 → [문]으로 뚫고 → [용도]"* | *"[용도] > [대기실]로 바닥을 드래그해 칠하고 → [의자]를 채웁니다."* 벽·문 전제 삭제 |
| 「모든 방에 문을 냅니다」 | `r.doors.size === 0`인 방을 밀실로 경고 | **「모든 영역에 길이 닿게 합니다」로 대체** — 판정은 도달성: `ENTRANCE`에서 통행 가능 타일 flood fill 한 번을 돌려, 영역 타일이 **전부** 도달 불가면 경고. 문 개념이 규칙에서 사라져도 "벽으로 두르고 문을 잊는" 실수는 여전히 가능하고, 그때 화면에는 멀쩡한 방으로 보이는 문제(현행 주석의 그 문제)도 여전하다 — 경고의 존재 이유가 유지되므로 단계를 지우지 않고 판정만 바꾼다 |
| 진료실·수납 hint | 벽 전제 문구 | 칠하기 문구로 갱신 |

## §6 테스트 전략

- **regions.test 재작성** — 새 정의를 재는 것으로: 성분 파생(같은 용도 이어 칠하면 하나) · 병합 · 분할 · dept 분리 · 벽/문 타일이 성분을 끊는 게 아니라 **애초에 칠해지지 않음** · id 결정론 · 캐시(uncached 대조, 현행 관례).
- **build.test** — paintZone: 사각형 칠·벽/문 skip·같은 용도 skip·다른 용도 덮어쓰기·`NOTHING`·EXAM dept throw. eraseZone: 범위 지우기·빈 범위 `NOTHING`.
- **소비자 테스트** — `testHelpers.placeRoom`(벽 두르고 문 내고 앵커 지정)이 내부적으로 `paintZone`을 쓰도록 바뀌면 기존 픽스처는 무변. 벽·문을 계속 두르는 것도 유지한다(통행·시각은 여전히 벽의 몫이고, 기존 테스트의 동선 전제가 흔들리지 않는다).
- **도달성 경고** — 벽으로 완전히 두르고 문 없는 영역 → 경고, 문 내면 해소, 열린 영역(접수처) → 경고 없음.

## §7 하지 않는 것 (YAGNI)

- **밀폐·프라이버시 보너스 규칙 신설 없음** — 벽은 통행 차단과 시각으로만 남는다. 벽의 게임적 존재 이유가 약해지는 것은 알고 있으나, 그 보상 설계는 별건이다.
- 영역 이름 짓기·색 커스텀·자동 영역 제안 없음.
- 저장 마이그레이션 없음(저장 기능이 아직 없다).
- 오버레이 테두리 등 새 시각 장치 없음(§4).

## §8 미해결 (후속 판단)

- **한 타일 영역**(카운터 한 칸만 접수처로 칠하기)이 규칙상 유효하다 — 슬롯 파생이 정상 동작하는지는 구현에서 테스트로 확인하고, 어색하면 최소 크기 제약을 후속으로 단다.
- 도달성 경고의 판정 비용(ENTRANCE flood fill)은 setupSteps 호출 빈도에 좌우된다 — 구현에서 호출 지점을 보고 필요하면 memo(현행 regions memo와 같은 참조 키 방식)를 단다.
