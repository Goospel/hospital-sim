# HUD 밝은 전환 — 아트 디렉션 ④ (본편 한정 토큰 스코프 반전)

> 2026-08-01 · 사용자 지시: *"HUD도 밝게 바꾸자 (④ 단계)"*
> 관련: [밝은 아트 디렉션 ①](2026-07-31-bright-art-direction-design.md)(범위 정의 — ④가 이 문서) ·
> [밝은 랜딩](2026-07-31-bright-landing-design.md)(팔레트·패턴의 출처 — 이 문서는 그 확장)

## §0 문제

게임 캔버스(#178)와 랜딩(#180)은 밝은 병원 톤인데, 그 사이의 모든 UI —
HUD 상단바·사이드바·채용 패널·이벤트 카드·하루/주간 오버레이 — 는 어두운 desk 토큰
위에 있다. 밝은 랜딩에서 지역을 확정하는 순간 어두운 개원 준비 다이얼로그가 떠서
명암이 널뛴다.

## §1 확정 결정 (사용자 선택)

| # | 결정 | 이유 |
|---|---|---|
| 1 | **본편(`/`)만 전환** — `/classic`은 어두운 채 유지 | 옛 판은 어두운 전제로 설계된 은퇴 제출물(20파일·284곳). 전수 검수 비용을 피하고, desk 토큰의 `:root` 값은 옛 판의 소유로 남긴다 |
| 2 | **토큰 스코프 재정의 방식** | 아래 §2 |

## §2 방식 — SimGame 루트에서 desk 토큰 6종 재정의

`globals.css`의 `@theme inline`이 유틸리티에 `var(--desk)` 참조를 **직접** 심으므로
(빌드 시점 hex 아님 — 구현 전 확인 완료), 커스텀 프로퍼티는 사용 지점에서 해석된다.
따라서 **SimGame 루트 요소에서 `--desk`·`--desk-2`·`--frame`·`--on-desk`·
`--on-desk-muted`·`--alarm` 6종을 밝은 값으로 재정의**하면:

- 본편 하위의 desk 토큰 사용 99곳(SimGame 46 · HirePanel 21 · PriorityPanel 18 ·
  WeekEndOverlay 4 · TileMap 6 · EventCard 2 · DayEndOverlay 2)이 **클래스 무변으로** 뒤집힌다.
- 알파 수식어(`bg-desk/85` 등)는 Tailwind v4가 `color-mix(… var(--desk) …)`로 뱉어
  런타임 해석되므로 함께 뒤집힌다.
- `/classic`(SessionClient 이하 20파일)은 `:root` 값 그대로 어둡다.
- 값은 `landingPalette.ts`에서 주입 — **hex는 TS에만**(랜딩 §3과 같은 계약).
  `globals.css`는 무변.

기각한 대안: ⓐ `globals.css` 값 교체(클래식까지 뒤집힘 — §1-1 위반)
ⓑ 99곳 클래스 전수 교체(diff 거대·실수 표면·랜딩이 확립한 변수 패턴과도 어긋남).

## §3 토큰 대응 — 극성을 쌍째 뒤집어 대비 구조 보존

배경과 글자가 **쌍으로** 반전되므로 기존 조합(`bg-desk-2` 위 `text-on-desk` 등)의
대비 관계가 보존된다. 랜딩 팔레트를 그대로 재사용해 랜딩 → HUD가 같은 종이 톤이 된다.

| 토큰 | 역할 | 밝은 값 (LANDING 키) |
|---|---|---|
| `--desk` | 화면 바탕·딤 | `backdrop` |
| `--desk-2` | 패널·카드 | `card` |
| `--frame` | 테두리·버튼 면 | `edge` |
| `--on-desk` | 본문 | `ink` |
| `--on-desk-muted` | 보조 텍스트 | `inkMuted` |
| `--alarm` | 경고 | **`alarmDeep` 신설** — #e5484d는 밝은 카드 위 대비 미달. 색상 유지, 카드 위 WCAG 4.5:1을 테스트로 잠그는 값으로 하향 |

## §4 HUD 위계 — 분리의 방향이 뒤집힌다

어두운 시절 HUD는 캔버스보다 **어두워서** 분리됐다. 밝은 판에서는 종이 카드
(휘도 234)가 캔버스 부지(176)보다 **밝아서** "위에 뜬 카드"로 분리된다 —
「부지가 배경보다 밝다」 계약과 같은 방향이라 충돌이 없다. `backdrop-blur` 5곳은
유지(어두운 반투명 유리 → 밝은 반투명 유리로 자연 전환).

## §5 청록은 주요 확정 버튼에만

랜딩의 「여기에 짓는다」와 같은 축으로, **진행을 확정하는 버튼 셋만** 수술복 청록
(`LANDING.accent` + `onAccent`):

1. HirePanel 「개원 준비 시작」
2. DayEndOverlay 「다음 날」
3. WeekEndOverlay 「다음 주」(결말 분기의 진행 버튼 포함 여부는 구현에서 화면 보고 판단)

나머지 버튼·토글·도구 선택은 중립(frame 계열) 유지 — 청록이 흔해지면 확정의 뜻을 잃는다.
hover가 필터를 쓰면 **어둡게 하는 방향만**([T-142](../../../claude-docs/troubleshooting/T-142.md)).

## §6 계약을 테스트로

`landingPalette.test.ts` 확장(새 파일 없음):

1. `alarmDeep`: 카드 위 WCAG 4.5:1 이상 + 색상각이 기존 `--alarm`(#e5484d)과 같은
   빨강 대역임을 잠글 필요는 없다(색상은 눈 검수) — 대비만 잠근다.
2. 기존 서열·간격·고정점 테스트 무변 통과.

자동 반전이 계약을 못 지키는 자리 — 알파 수식어 16곳·`bg-alarm/10`·blur — 는
**브라우저 전 화면 검수**가 게이트다: 채용 → 건설 → 하루 정산 → 주간 결산 →
이벤트 카드 → 우선순위 패널 → 에필로그.

## §7 하지 않는 것 (YAGNI)

- `/classic` 20파일·284곳 무변. `globals.css` `:root`·`html,body` 배경 무변
  (본편은 Backdrop 캔버스가 화면을 채워 body 배경이 안 보인다).
- desk 토큰 이름 변경·토큰 체계 재설계 없음 — 값의 스코프 재정의만.
- 게임 캔버스(TileMap 그리기)·스프라이트 무변. 아트 디렉션 ②③⑤ 별건.
- 다크 모드 분기 없음.

## §8 미해결 → 구현에서 전부 해소 (2026-08-01 실측)

- **`alarmDeep` 최종 hex = `#b02a30`** — 카드 위 5.43 · 배경 위 4.71로 계약 통과.
  색상각은 기존 #e5484d와 0.78° 차라 "같은 빨강, 어둡게"가 수치로 성립한다.
- **`bg-alarm/10`·`border-alarm/60`은 그대로 둔다** — 카드 대비 1.16:1이라 바탕 구획은
  약하지만, 그 위 글자가 alarmDeep 4.66·ink 9.39로 읽히고 이 프로젝트는 색 단독 신호를
  쓰지 않는다(문구가 함께 진다). 실화면에서 칩으로 읽히는 것을 확인했다.
- **결말 오버레이는 해당 없음** — 폐업(CLOSED) 분기에는 진행 버튼이 **아예 없다**
  (에필로그 텍스트만). 청록은 「다음 주」에만 붙는다.
- **추가로 발견돼 고친 것**: 전역 `html { color-scheme: dark }`가 남아 밝은 패널의
  UA 스크롤바·선택 하이라이트가 어두웠다 — 루트 style에 `colorScheme: "light"`
  한 줄로 해소(상속 속성이라 자손 스크롤 컨테이너 6곳이 따라온다). `globals.css`는
  `/classic`이 그 값을 쓰므로 여전히 무변.
- **딤(`bg-desk/85`)은 밝은 안개가 된다** — 카드와의 휘도 차는 1.1~1.2로 얇지만,
  종이 카드의 **따뜻한 색조**와 드롭섀도가 분리를 지어 실화면에서 카드로 읽힌다.
  별도 어두운 딤 값을 신설하지 않았다(토큰 6종만 재정의한다는 §2를 지키는 쪽).
  더 강한 모달 초점이 필요해지면 그때 딤만 별도 값으로 뺀다.
