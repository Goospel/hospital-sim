# 채용 패널 그래픽 재설계 — 종이 명부 + 빈 자리 + 초상 변주

> 2026-08-03 · [전국 인력 시장 스펙](2026-08-03-talent-market-design.md)의 후속. 카드 시장의
> **구조**는 섰지만(#186) 시각 정체성이 없다는 사용자 피드백 — 회색 상자 카드, 40px 초상,
> 머리색4×피부색3=12조합뿐이라 18명 명부에서 같은 얼굴 반복. 사용자 결정: ① 콘셉트는
> **종이 명부 + 빈 자리** ② **머리 모양 변주 추가**(캐릭터 규약 개정 포함).

## §0 원칙

- **시뮬 무변.** `hiredSlots`·`hireDoctor`·`candidateOf` API 그대로 — 이번 변경은 표시 층(HirePanel·PixelSprite)뿐이다.
- **새 시각 문법 0.** 종이는 속보·결산이 이미 쓰는 `.paper-card`/`--paper`/`--ink` 토큰(globals.css 단일 출처)을 그대로 쓴다. 과 색은 `PixelSprite.DEPT_COLOR`를 그대로 쓴다.
- **캐릭터 규약 준수**: 얼굴 특징·표정 금지, 스프라이트에 아이콘·배지·이름표 금지, 그라디언트 금지(SVG), 새 이미지 에셋 0. 완화되는 것은 §3의 머리카락 형태 하나뿐이고 문서 개정을 동반한다.
- **해석 카피 0** — 기존 문구 전부 무변. 새 문구는 넣지 않는다.

## §1 종이 명부 (HirePanel)

- **패널 배경은 desk 유지, 후보 카드 개별이 종이가 된다** — 책상 위에 인사 서류 묶음이 놓인 그림. (패널 전체를 종이 한 장으로 하는 안은 기각: 속보·결산은 "문서 한 장"이지만 채용은 "여러 장의 명부"라 카드 단위가 콘셉트에 맞다.)
- **후보 카드(세로형)**, 위에서 아래로:
  1. **초상 스테이지** — 카드 폭 전체 × 높이 ~72px. 배경은 과 색 워시(`DEPT_COLOR[dept]`를 낮은 알파(12~18%)로 paper 위에 얹음), 중앙에 `DoctorSprite` **64~72px**(현행 40px에서 대형화).
  2. **이름** — `text-base`급, `text-ink`.
  3. **특성 칩 2** — 작은 테두리 칩(`border-rule` + `text-ink-2`).
  4. **사연 1줄** — `text-ink-3`(현행 문구 그대로 — traits.ts 계약 무변).
  5. **채용 버튼** — 종이 위 버튼: `border-border-paper` + `text-ink`, hover는 어둡게만(T-142). `aria-label="{이름} 채용"` 무변.
  - 카드 컨테이너는 `.paper-card`(그라디언트+이너하이라이트+섀도 일체). 텍스트는 전부 ink 계열 — on-desk 계열은 desk 위 전용이라 종이 위에 얹지 않는다.
- **열(과 섹션)**: desk 위 투명 배경. 헤더는 과명 + **과 색 언더라인(2px, DEPT_COLOR)**, 주급·현재·잔여 문구 무변.
- **간호사 줄·하단 바(주 고정비)·개원 버튼은 현행 desk 톤 그대로** — 간호사는 카드가 아니라는 계약(풀 없는 제약을 카드로 흉내 내지 않는다)이 톤 차이로도 읽힌다.
- 유지되는 계약: `role=dialog`+`aria-modal`, `my-auto`(T-088), 빈 과 사유 문구·「이게 전부입니다」(≤2), 스타팅 게이트 로직·문구, `onHire(dept, slot)`.

## §2 빈 자리 — 소비된 슬롯의 잔상 프레임

- **열의 자리 수 = 그 지역 풀 총량**(= `hirePool[d] + hiredSlots[d].length` — talent-market §2 불변식이 잠근 값). 슬롯 번호 순으로: 미소비 슬롯 → §1 종이 카드, **소비 슬롯 → 빈 프레임**.
- **빈 프레임**: `border-dashed border-border-paper` + 종이보다 흐린 배경(desk 위 paper-edge 저알파 워시) + **잉크 단색 실루엣 초상**(그 후보의 초상을 단색·opacity ~0.25로) + 이름(`text-ink-3` 흐리게). **라벨·사유 문구 없음** — "채용됨/떠남" 판정을 화면이 새로 하지 않는다(그 사람이 그 자리였고 지금 명단에 없다는 사실만 그린다). 채용 버튼 없음.
- **데이터**: props에 `consumed: Record<SimDeptKey, Candidate[]>` 추가 — 부모(SimGame)가 `hiredSlots`를 `candidateOf`로 매핑해 내려준다(화면이 세지 않는다 계약 유지). `candidateOf`가 순수라 이름·초상이 언제나 재현된다.
- 효과: 스타팅 게이트 시점엔 소비 0 → 전 열 만석(첫인상이 풍성). 게임이 진행될수록 빈 프레임이 누적 — **사직 비가역·인력 소진이 화면 구조가 된다**. 순환기 열은 자리 자체가 2칸(지역 축소 시 1칸)이라 짧은 열이 곧 인력난이다.
- 빈 과(잔여 0): 빈 프레임들 아래에 현행 사유 문구 유지.

## §3 머리 모양 변주 (PixelSprite)

- `spriteVariant(key)` → `{ hair, skin, hairStyle }`. **머리카락 path 3종**: ⓪ 현행 아치 ① 가르마(호를 좌우 비대칭 2분할 — 이마 선이 한쪽으로 치우침) ② 짧은 올림(호 높이를 낮추고 이마 라인을 위로). 전부 머리카락 path 데이터만 다르다 — **얼굴 특징 추가 없음, 몸 실루엣 무변**.
- 해시 축 분리: `hair = u % 4`, `skin = (u/7) % 3`(현행), `style = (u/29) % 3`(새 축 — 서로 다른 제수로 독립). 12 → **36조합**.
- 적용 대상: `variantKey`를 받는 모든 인물(의사 카드·맵 폰·간호사) — **카드의 그 사람 = 맵의 그 사람** 계약 무변(키=이름).
- **character-design.md §1 개정 동반**: "실루엣은 하나를 공유하고 팔레트만 다르다" → "**몸 실루엣**은 하나를 공유(주제 근거 무변)하고, 변주는 **팔레트 + 머리카락 형태 3종**" + 개정 사유(18명 명부 대형 초상에서 12조합 반복 실측 · 2026-08-03 사용자 결정).

## §4 테스트 (TDD — Red 먼저)

1. `spriteVariant` 결정론: 같은 키 → 항상 같은 `{hair, skin, hairStyle}`. `hairStyle ∈ {0,1,2}`. 축 독립: 스타일이 다른 두 키에서 hair가 같을 수 있음을 실례로 확인(조합 수 과잠금은 하지 않는다).
2. HirePanel 자리 수: 열 렌더 수 = `candidates[d].length + consumed[d].length`. 빈 프레임에는 채용 버튼이 없고, 소비 후보의 이름이 표시된다.
3. 기존 UI 테스트 전원 무변 통과(채용 클릭이 그 슬롯으로 `onHire`, 스타팅 게이트, 빈 과 문구, 「이게 전부입니다」).
4. 대비: 종이 위 본문(ink/paper) 4.5:1 — 기존 팔레트 테스트가 이 조합을 이미 잠그는지 확인하고, 없으면 한 줄 추가.

## §5 범위 밖 (의도적 절단)

- 시뮬 변경 전무. 풀 숫자·밸런스 무변.
- 간호사 카드화 금지 유지.
- 카드 사라짐/등장 애니메이션 — 구현 재량(넣어도 되지만 요구가 아니다).
- 지도·타일맵 등 다른 화면의 종이화 — 이번 범위 밖.
