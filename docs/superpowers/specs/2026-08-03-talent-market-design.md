# 전국 인력 시장 — 채용 패널 대개편 (후보 실체화 + 카드 UI)

> 2026-08-03 · 사용자 지시: *"인력풀이 너무 적어 보여 볼품없다 — 페이지를 큰 규모로,
> 그래픽적으로 바꿔도 좋다"* → 시안 B(인재 카드 시장) 확정, **풀 숫자는 유지**.

## §0 문제

채용 패널([HirePanel.tsx](../../../src/components/HirePanel.tsx))이 "전국 잔여 2명"을
회색 숫자 한 칸으로만 보여준다. 풀 숫자(미용 8·내과 5·외과 3·순환기 2)는 게임의
논지(사직 비가역·필수과 인력난·지역 격차)를 싣는 의도값인데, **숫자로만 서 있으니
의도된 희소성이 아니라 콘텐츠 부족으로 읽힌다.**

## §1 확정 결정 (사용자 선택)

| # | 결정 | 이유 |
|---|---|---|
| 1 | **시안 B — 인재 카드 시장** (시안 A 토큰 강화 기각) | 희소성이 "숫자 2"가 아니라 "이 사람 둘"로 읽히게 한다. 이름·특성·초상 재료가 코드에 이미 있다 |
| 2 | **풀 숫자 유지** (확대 기각) | 사직의 무게·대소 서열·지역 격차가 이 값에 걸려 있다(dept.ts §nationalPool 주석) — 표현만 바꾼다 |

## §2 시뮬 층 — 후보 실체화 (유일한 시뮬 변경)

### 지금 (채용 시점 서수 배정)

- 이름: `doctorName(hiredEver)` — 풀 소진량 합이 서수. **뽑기 전에는 누가 올지 정해져 있지 않다.**
- 특성: `pickTraits(nextId)` — 전역 카운터라 **언제 뽑느냐**에 따라 달라진다.

### 바꾼 뒤 (개원 시점 슬롯 고정)

**`(과, 슬롯 번호) → {이름, 특성 2, 초상키}`를 순수 함수로 만든다** — RNG 0, 시드 무관,
세계 상태 무관. 후보는 개원 순간부터 사람이고, 카드에 미리 보인다.

- **이름 배정 — 전국 풀 기준 전역 분할.** `DOCTOR_NAMES` 18개를 전국 풀 합계(8+5+3+2=18)에
  1:1로 나눈다: 전역 슬롯 = 과 오프셋(미용 0·내과 8·외과 13·순환기 16) + 과내 슬롯.
  과가 달라도 이름이 절대 안 겹친다(현행 "판 안 동명이인 없음" 계약 유지·강화).
- **특성 배정.** `pickTraits(전역 슬롯)` — 기존 산식 재사용(두 특성이 항상 서로 다름은 산식이 보장).
  `nextId` 의존이 사라져 **같은 후보는 언제 뽑아도 같은 사람**이다.
- **지역 축소 풀.** 지역 델타로 줄어든 과는 **과내 슬롯 0..N−1만 존재**한다
  (예: PROVINCIAL 순환기 = 슬롯 0 한 명). regionHirePool은 무변.

### 세계 상태 — `hiredSlots` 추가

```ts
// SimWorld에 추가
hiredSlots: Record<SimDeptKey, number[]>   // 과별로 이미 뽑힌 슬롯 (빈 배열로 시작)
```

- `hireDoctor(w, dept, slot)` — 그 후보를 소비한다. 검증: 슬롯 범위(지역 풀 기준)·미소비.
  실패는 기존 `NO_POOL`에 더해 슬롯이 이미 소비된 경우도 같은 형태로 거부한다.
- **`slot`은 필수다**(구현 시 정정 — 설계 초안의 "생략 시 남은 최소 슬롯" 하위호환은 기각).
  근거는 리뷰 실측이다: optional 폴백이 있으면 화면(SimGame)이 slot을 떨어뜨려도 tsc와
  테스트 1596건이 **전원 통과**하면서 카드에서 고른 사람이 아닌 다른 사람이 조용히 선다 —
  이 슬라이스의 논지가 어떤 계측기에도 안 걸리는 유일한 회귀 경로였다. 경고 주석은 벨트가
  아니다: 필수로 올리면 그 회귀가 **컴파일 에러**가 된다(런타임 비용 0·새 테스트 0).
  기존 손세계 픽스처를 위한 "남은 최소 슬롯" 폴백은 테스트 헬퍼(`testHelpers.hire`)로 옮겼다 —
  프로덕션은 사람을 지목하고, 픽스처만 아무나 뽑는다.
- `hirePool` 카운트는 **그대로 두고**(기존 테스트·화면·이벤트가 전부 이 값을 읽는다)
  두 값의 일치를 불변식 테스트로 잠근다:
  `hirePool[d] + hiredSlots[d].length === regionHirePool(region)[d]`.
  쓰기 경로가 `hireDoctor` 하나뿐이라 이중 기재의 drift 면은 없다(설계상 인정하는 잉여).
- `spawnDoctor`는 신원(이름·특성)을 **인자로 받는다**(옵션). 미지정 시 현행 폴백(서수 0
  손세계 폰) 유지 — 테스트 손세계가 안 깨진다.
- **사직·풀 비가역·간호사(풀 없음)·특성 무효과(표시 전용)·채용 일시금 없음 — 전부 무변.**

### 마이그레이션 주의

- 이름을 서수로 잠근 기존 테스트(traits.test 등)는 **전역 분할 기준으로 갱신**된다 —
  첫 채용이 항상 김서준이 아니라, 과에 따라 그 과 몫의 첫 이름이 온다.
- 저장 호환은 **없다**(확인 완료): `SimWorld`는 어디에도 직렬화되지 않는다(localStorage
  사용처는 옛 층·storyteller뿐). 마이그레이션 코드를 만들지 않는다.

## §3 UI 층 — HirePanel 대개편

- **좁은 모달(max-w-md) → 넓은 오버레이(max-w-4xl 급).** 과별 **4열 그리드**(좁은
  화면은 2열→1열), 열 머리에 과명·주급·잔여 N. **열 높이 차이 자체가 인력난 시각화다**
  (미용 8장 스택 vs 순환기 2장).
- **후보 카드**: 초상(기존 `PixelSprite` 사람 벡터 + 과 가운색 + `spriteVariant`) ·
  이름 · 특성 칩 2개 · 사연 한 줄(`TRAITS[k].story` 중 첫 특성 것) · 채용 버튼.
  새 이미지 에셋 0개.
- **초상 키 = 이름.** 맵 아바타의 `spriteVariant` 키도 이름으로 맞춰 **카드의 그 사람이
  맵에서도 같은 얼굴**이 되게 한다(현행 키가 다르면 TileMap 쪽을 이름 키로 통일).
- **소진 표현**: 뽑힌 자리는 목록에서 사라진다. 풀이 빈 열은 기존 사유 문구("전국에 남은
  … 없습니다 — 떠난 사람은 돌아오지 않습니다")가 빈 자리를 채운다. 순환기처럼 마지막
  한두 장 남은 열의 바닥에는 "이게 전부입니다" 한 줄(해석 카피가 아니라 사실 진술).
- **간호사**: 하단 고정 줄(카드 아님 — 풀이 없는 제약을 카드로 흉내 내지 않는다, 현행
  주석의 계약 유지). 문구·주급 표시 무변.
- **하단 바**: 주 고정비 합계 · 스타팅 진행(0/3) · 개원 준비 시작(청록 확정 버튼) — 현행 유지.
- **유지되는 계약**: `role=dialog` + `aria-modal`, 세로 가운데 `my-auto`(T-088),
  풀 빈 과 버튼 disabled + 코어 NO_POOL 토스트 이중 벨트, 스타팅 게이트(의사 3명, 간호사
  불산입), 밝은 HUD 토큰(desk 계열 — SimGame 루트 재정의를 그대로 탄다), hover 시 밝히지
  않기(T-142).
- **호출부(SimGame)**: `onHire(dept)` → `onHire(dept, slot)`.

## §4 테스트 (TDD — Red 먼저)

1. 후보 함수 결정론: 같은 (과, 슬롯) → 항상 같은 이름·특성. 세계 상태·nextId와 무관.
2. 이름 유일성: 4과 전 슬롯 18개의 이름이 서로 다르다. 지역 축소 풀에서도 부분집합이라 자동 성립.
3. 슬롯 소비: `hireDoctor(w, dept, slot)`이 정확히 그 후보의 이름·특성으로 폰을 세운다.
   이미 소비된 슬롯·범위 밖 슬롯은 거부(세계 무변).
4. 불변식: 임의 채용 열 뒤 `hirePool[d] + hiredSlots[d].length === regionHirePool(region)[d]`.
5. 픽스처 폴백: `testHelpers.hire(w, dept)` = 남은 최소 슬롯 채용(코어가 아니라 헬퍼의
   성질이다 — §2 정정). 손세계 `spawnDoctor` 직접 호출 무변.
6. UI: 열별 카드 수 = 잔여 풀, 카드 채용 클릭이 그 슬롯으로 `onHire` 호출, 빈 열 사유 문구,
   스타팅 게이트 동작 무변.

## §5 범위 밖 (의도적 절단)

- 풀 숫자·밸런스 변경(사용자 결정으로 기각).
- 특성의 수치 효과(기존 절단 유지 — traits.ts 머리말).
- 간호사 후보 카드화(풀이 없는 제약을 카드로 흉내 내지 않는다).
- 후보 리롤·재보충·스카우트 같은 신규 메커니즘(새 결정을 낳지 않는 이번 범위 밖).
