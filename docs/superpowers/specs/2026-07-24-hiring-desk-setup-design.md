# 설계 스펙 — 채용 데스크: SETUP 위저드 게임화 (지원서 + 도장)

> **상태**: 확정 설계 (2026-07-24, brainstorming). 다음 = writing-plans로 구현 계획. **구현은 별도 세션(Opus)이 수행한다.**
> **맥락**: 사용자 방향 — *"초기 세팅 페이지를 좀 더 게임처럼. 의사 초상화·약력·요구 연봉까지 게임에 녹이고 싶다."* 현행 SETUP은 과별 +/- 카운터라 "누구를 뽑는가"의 게임 감각이 없다.
> **원칙 충돌과 해소**: [character-design.md](../../concept/character-design.md) §2·§6이 "초상화·개인 서사"를 의도적 보류로 못박았다. 사용자 결정(브레인스토밍)으로 **이력서 방식**을 채택 — 초상(픽셀 확대)·기계적 사실(연차·경력·계약금)은 허용하되 **성격·사연·감정 서사는 계속 금지**. "시스템이 문제"가 개인 드라마로 미끄러지지 않는 선을 지킨다. 이 스펙이 그 문서의 §2·§6 개정을 포함한다(§7).
> **관련**: [2026-07-23 병원 맵 스펙](2026-07-23-hospital-map-design.md) — 픽셀 스프라이트·명단(roster)의 출처. [2026-07-24 재미 개선 스펙](2026-07-24-emergency-agency-fun-design.md) — "실질 결정이 위저드에 몰려 있다"는 진단; 이 스펙은 그 위저드 결정 자체를 더 게임답게 만든다.

## 1. brainstorming 확정 결정 (사용자 선택)

| 축 | 결정 |
|---|---|
| 게임화 수위 | **이력서 방식** — 초상화(기존 8×8 픽셀 확대) + 기계적 사실만(연차·한 줄 경력·요구 계약금). 성격·사연·감정 서사 없음 |
| 경제 침습 | **채용비만 변동** — 지원자별 요구 계약금(일회성). 주간 고정비·7의 배수 불변식·CALL_ECONOMICS는 0 침습 |
| 경력의 가치 | **진료 속도** — 베테랑은 환자를 빨리 본다(busyUntil 점유 단축). "싼 신입이 항상 정답"을 막는 축 |
| 지원자 풀 | **고정 풀** — 과별 4명, 코드에 박힌 결정론 데이터(RNG 0). 리롤·시드 없음 |
| UI 형태 | **채용 데스크(A안)** — 과별 아코디언 + 지원서 카드 + 「채용」 도장 토글. 면접 시퀀스(B안)는 30회 강제 진행이라 기각, 현행 +/- 유지(C안)는 게임 감각 부재로 기각 |

## 2. 지원자 풀 — `src/game/candidates.ts` (신규 모듈)

과별 지원자 **4명** × 8과 = 32명. 전부 코드에 박힌 고정 데이터(결정론 — 같은 게임은 항상 같은 지원자).

```ts
export type CareerTier = 'ROOKIE' | 'STANDARD' | 'VETERAN'

export interface Candidate {
  id: string            // 'cand-<DEPT>-<n>' — 고유·안정(테스트·명단 파생 키)
  name: string          // 한글 이름 — 기존 FAMILY_NAMES·GIVEN_NAMES 어휘와 충돌 없는 고정값
  dept: DeptKey
  tier: CareerTier
  careerYears: number   // 표시용 연차 — tier와 정합(신입 0~2, 중견 5~9, 베테랑 12~20)
  resumeLine: string    // 한 줄 경력 — 기계적 사실만(§7 금지선)
  hireCostManwon: number // 요구 계약금 = 과 앵커 × 티어 배율, 정수(만원)
}
```

### 티어 배율 — 계약금과 속도가 한 쌍

| tier | 계약금 배율 | speedFactor(진료 시간 배율) | 과별 인원 |
|---|---|---|---|
| ROOKIE | ×0.7 | ×1.15 (느림) | 1명 |
| STANDARD | ×1.0 | ×1.0 | 2명 |
| VETERAN | ×1.3 | ×0.8 (빠름) | 1명 |

- **speedFactor는 tier에서 파생한다**(`SPEED_OF_TIER: Record<CareerTier, number>`). Candidate에 중복 저장하지 않는다 — 이중 기재 병 방지.
- 계약금 = `Math.round(dept.hireCostManwon × 배율)`. 앵커가 setup.ts의 기존 값이므로 **"순환기 1명 = 미용 3명" 비율 딜레마가 보존**된다. 베테랑 순환기 3명 = 19,500×3 = 58,500만원 > 예산 50,000만원 — 올(all) 베테랑 필수과는 불가능, 선택이 강제된다.
- 계약금은 일회성 채용비다. **주간 고정비(`fixedCostPerDoctorManwon`)는 티어와 무관하게 현행 유지** — 7의 배수 불변식·결말 장부·명랑 장부에 0 침습.

### resumeLine 작성 규칙 (금지선)

- **허용**: 근무처 유형·업무·기간 등 기계적 사실. 예 — "대학병원 심도자실 12년" / "전공의 수료 직후" / "2차병원 야간 당직 6년" / "검진센터 내시경 전담 7년".
- **금지**: 성격("다혈질"), 감정·사연("가족을 잃고"), 평가·해석("실력파", "워커홀릭"), 대사. 이 게임에서 의사는 여전히 **자리**다 — 이력서는 자리의 스펙 시트이지 인물 소개가 아니다.
- 이름·경력은 실존 인물·기관을 특정하지 않는다(제출물 — 기존 `FORBIDDEN_REAL_EVENT_TOKENS` 정신).

## 3. 타입·경제 — 추가 방식(비파괴), 침습 최소화

### SetupChoices — `hiredIds` 추가, `doctors`는 파생으로 유지

```ts
export interface SetupChoices {
  hospitalName: string
  doctors: Record<DeptKey, number> // 기존 — 유지(성장·경제·티어 등 모든 소비처 무수정)
  hiredIds?: string[]              // 신규 — SETUP에서 채용한 지원자 id 목록
}
```

- **단일 기록 지점**: 위저드는 `hiredIds`만 조작하고, `doctors` 카운트는 `hiredIds`에서 **파생 함수로 계산**해 `onComplete` 시점에 한 번 채운다(`doctorsCountsOf(hiredIds)`). 두 필드를 각자 조작하는 경로를 만들지 않는다 — drift 구조적 차단.
- `hiredIds`가 없는 choices(기존 테스트·성장 경로)는 전부 현행대로 동작한다(옵셔널 + 파생이라 하위호환).

### 예산 검사 — 지원자 합산으로 교체 (SETUP에서만)

- 신규: `hiringCostOfCandidates(hiredIds): number` — 지원자 계약금 합산.
- `isSetupReady`·위저드 예산 표시가 이 함수를 쓴다. **성장 단계의 중도 채용은 현행 앵커가(`dept.hireCostManwon`) 유지** — 중도 채용은 무명·표준가라는 규칙이 그대로 사실이 된다.
- 과별 상한(`deptCap`)은 지원자 수(4)와 독립적으로 현행 유지(SETUP cap 3). 풀 4명 > cap 3이라 "누굴 버릴 것인가"가 항상 존재한다.

### 명단 — `materializeRoster` 확장

- SETUP 채용분: `hiredIds` → 해당 Candidate의 `name`·tier 파생 `speedFactor`로 `Doctor` 생성. **이력서의 그 사람이 그대로 명단에 온다.**
- 성장 중도 채용분(카운트가 지원자 수를 초과하는 만큼): 현행 결정론 이름 생성(`doctorName(k)`)으로 채움, `speedFactor` 1.0.
- `Doctor`에 `speedFactor?: number`(기본 1.0)와 초상 변주 키(`candidateId?: string`) 추가 — 옵셔널이라 기존 생성 경로 무수정.

## 4. 판정 — 진료 속도 (침습 1지점)

- `decide()`(receiving.ts)의 점유 계산 한 줄: `busyUntil[doc.id] = arrivalMin + durationMin` → `arrivalMin + Math.round(durationMin × (doc.speedFactor ?? 1.0))`.
- 같은 계산을 하는 다른 지점(예약 자동 디스패치·워크인 자동 수용·BUMP 재점유 등)이 있으면 **헬퍼 하나로 묶는다**: `occupiedUntil(doc, arrivalMin, durationMin)`. 계산식이 두 곳에 살면 한쪽이 낡는다.
- 효과의 방향: 베테랑이 있는 과는 몰릴 때 회전이 빨라 대기 이탈(patience 초과)이 줄어든다 — 현행 과부하 원인("도착이 뭉칠 때 의사가 이미 진료 중")에 정확히 꽂히는 축.
- **돈에는 0 침습**: 콜 수익·원가는 건당이라 속도와 무관. 속도는 "몇 건을 받아낼 수 있는가"를 통해서만 간접적으로 경제에 닿는다(창발 — 입력이 아니라 계산에서).

## 5. UI — SetupWizard DEPTS 단계 개편 (채용 데스크)

- **과별 아코디언** — 한 번에 한 과만 펼침(32장 동시 노출 방지). 접힌 헤더: 과명 · 채용 n/상한 · 그 과 계약금 소계. 초기엔 첫 과가 펼쳐진 상태.
- **지원서 카드** — 기존 `paper-card` 재사용(위저드의 "종이는 예산 장부 1장" 규칙은 "종이 = 서류"로 재해석: 지원서도 종이다). 카드 구성:
  - 좌: 픽셀 증명사진(§6)
  - 우: 이름 · 연차 · resumeLine · 요구 계약금 · 평균 진료 시간 배율(사실 숫자만, 예 "진료 소요 ×0.8" — 해석 카피 없음)
- **채용 = 도장 토글**: 카드 탭 → 「채용」 도장이 찍힘(기존 stamp 계열 클래스·살짝 회전). 다시 탭 → 도장 제거(반려). 상한 도달 시 미채용 카드는 비활성(예산 초과는 현행처럼 장부의 「예산 초과」 도장이 담당 — 화면당 도장 의미는 겹치지 않게).
- 버튼 시맨틱: `<button aria-pressed>` — 키보드·스크린리더 경로 유지.
- 하단 현행 유지: 자격 사다리 패널 · 채용 예산 장부(합산만 `hiringCostOfCandidates`로 교체) · 「병원 개원」 버튼.
- NAME 단계는 무수정.

## 6. 초상화 — 이력서의 얼굴이 맵을 걸어다닌다

- **실루엣은 기존 8×8 `FIGURE` 그대로**(새 실루엣 금지 — character-design §5 체크리스트 준수). 지원자별 변주는 **머리색·피부톤 팔레트 2슬롯만** id 해시로 결정론 파생(작은 고정 팔레트 세트에서 선택 — 예: 머리 4색 × 피부 3톤).
- `PixelSprite`에 옵셔널 변주 프롭 추가(기본값 = 현행 렌더와 동일 — 스냅샷 하위호환). 과 색 어깨·"필수과 유채색 / 수익과 회색" 대조 규칙은 그대로.
- **증명사진** = 같은 스프라이트를 CSS 확대(`image-rendering: pixelated`) — 이미지 파일 0개, 정적 export 안전.
- **맵 연속성**: HospitalMap 아바타가 roster의 `candidateId`로 같은 변주를 적용 → SETUP에서 도장 찍은 그 얼굴이 개원 후 맵에 나타난다. 무명 중도 채용은 변주 없이 현행 렌더(과 색만) — "이력서 없이 온 사람"이 시각적으로도 구분된다(show-don't-tell).

## 7. 문서 개정 — character-design.md §2·§6

이 스펙 구현 PR에 포함한다(코드와 문서가 같이 움직인다):

- §2 "성격·사연·초상화는 없다" → **"성격·사연·감정 서사는 없다"**로 좁히고, 허용된 것(픽셀 초상 확대·기계적 약력·요구 계약금·티어 파생 진료 속도)과 그 이유(2026-07-24 사용자 결정, 이 스펙 링크)를 명기.
- §6 표의 "캐릭터 초상화·프로필 UI" 행 → 보류 해제 이력을 남기고(지우지 않는다 — promoted 이력 보존 원칙과 동형), **금지가 유지되는 것**(감정 표현·개인 사연·환자 개인화·대사)을 같은 행에 재확인.
- §0 단일 출처 표에 `candidates.ts`(지원자 데이터) 행 추가.

## 8. 테스트 계획 (TDD — Red 먼저)

| 대상 | 검증 |
|---|---|
| 풀 정합성 | id 유일 · 과별 정확히 4명(1/2/1 티어 구성) · 계약금 = 앵커×배율 반올림 · resumeLine 비어있지 않음 |
| 예산 | `hiringCostOfCandidates` 합산 · 베테랑 필수과 풀구성이 예산 초과인 밸런스 사실 · `isSetupReady` 연동 |

| 판정 | `decide()` 수용 시 베테랑 점유 = arrival + round(duration×0.8) · 무필드 의사 = 현행과 동일(1.0) |
| UI 로직 | 도장 토글(채용↔반려) · 상한 도달 시 비활성 · 예산 초과 도장 표시 |
