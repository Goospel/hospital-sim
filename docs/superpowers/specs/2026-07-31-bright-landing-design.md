# 랜딩(지역 선택) 밝은 재설계 — 종이 위 잉크 지도

> 2026-07-31 · 사용자 방향 지시: *"랜딩페이지 디자인 변경하자. 지금까지 변경한 것과 통일성 있게."*
> 관련: [밝은 아트 디렉션 ①](2026-07-31-bright-art-direction-design.md)(본편 팔레트 전환 — 이 문서는 그 랜딩판) ·
> 진행 순서상 ④ HUD 단계보다 랜딩이 앞서 간다(첫인상이 먼저다).

## §0 문제

본편은 밝은 병원 톤으로 전환됐는데(실내 바닥 휘도 ~210대, 부지 `OUTSIDE_FLOOR` 176), 첫 화면인
지역 선택은 여전히 어두운 `desk` 토큰(#101014·#17171c) 위에 있다 — 게임을 켜면 **어두운 화면이
먼저 나오고, 지역을 고른 뒤에야 밝아진다.** 첫인상이 아트 디렉션과 정반대다.

## §1 확정 결정 (사용자 선택)

| # | 결정 | 이유 |
|---|---|---|
| 1 | **화면 전체를 밝게** — 반투명 딤(85%) 대신 불투명 밝은 배경 | 첫 화면 전체가 밝은 병원 톤. 뒤의 어두운 HUD는 완전히 가려지고, 고르면 밝은 게임 화면으로 이어진다. (카드만 밝게는 화면 절반이 어둡게 남아 기각) |
| 2 | **수술복 청록 한 점 도입** — 선택 표식과 「여기에 짓는다」에만 | 흰색+청록이라는 병원 대표색 결정(아트 디렉션 §2)과 일치. 지도 자체는 여전히 단색이라 기존 원칙(타입별 색 금지)도 지킨다. (완전 단색 유지는 확정 버튼의 존재감이 약해 기각) |

## §2 색 체계 — 극성 반전, 서열 유지

현행 랜딩의 명암 서열은 "육지는 바탕이고 점이 내용이다"(RegionPicker 주석 · 밝을수록 내용).
밝은 화면에서는 **어두울수록 내용**이므로 극성만 뒤집고 서열은 유지한다:

```
점(가장 어둡다) < 육지 < 화면 배경 < 카드(가장 밝다)
```

| 층 | 현행 | 변경 |
|---|---|---|
| 화면 배경 | `bg-desk/85` 반투명 막 | 불투명 밝은 중성 — 본편 실내 벽 톤(`NEUTRAL_STYLE.wall` #e0e5ea) 대역 |
| 카드(패널) | `desk-2` | 흰 종이 — 배경보다 한 단 밝게(카드가 무대. 배경 팔레트의 「부지가 배경보다 밝다」와 같은 계약) |
| 지도 육지 | 옅은 베이지 25% | 중간톤 회색 — 종이에 인쇄된 지도. 카드와 점 양쪽에서 충분히 떨어진 중간 |
| 지역 점 | 밝은 베이지 | 진한 잉크 — 본편 외곽선 잉크(#181426) 대역 |
| 텍스트 | 베이지 | 잉크색 본문 + 회색 보조(muted) |
| 선택 점·선택 테두리·확정 버튼 | 베이지 | **수술복 청록** — 화면의 유일한 유채색 |

- 청록은 간호사 코트 `#4fa39e`(PixelSprite)에서 출발하되, 밝은 배경 위 대비를 실측해 필요하면
  진한 쪽(`#37827e` 계열)으로 조정한다. **확정 hex는 코드가 단일 출처다**(아트 디렉션 §0 규약) —
  이 문서에는 대역과 서열만 남긴다.
- hover·focus-visible은 현행 구조 유지(점이 진해지는 대신, 밝은 판에서는 점이 청록으로 기운다 —
  선택 전 미리보기와 선택 후가 같은 색 축을 쓴다).

## §3 값의 자리 — desk 토큰 불가침, TS 상수 단일 출처

- **`globals.css`의 `desk` 토큰은 건드리지 않는다.** HUD·사이드바가 그 토큰 위에 있고, HUD 전환은
  아트 디렉션 ④ 단계의 몫이다. 랜딩만 앞서 간다.
- 랜딩 전용 팔레트를 **TS 상수 모듈 하나**(`src/components/landingPalette.ts`)에 두고 RegionPicker가
  그것만 쓴다(inline style 또는 tailwind arbitrary value). CSS 변수를 신설하지 않는 이유:
  값이 TS에 있어야 휘도 서열을 **테스트로 잠글 수 있다**(§4). ④ HUD 때 이 값이 HUD 토큰의
  출발점이 된다.

## §4 계약을 테스트로

`backdropPalette.test.ts` 관례("스펙이 곧 테스트다") 그대로, `landingPalette.test.ts` 한 파일이 잠근다:

1. **휘도 서열**: 점 < 육지 < 배경 < 카드 (§2의 사슬).
2. **최소 간격**: 인접 층 사이 휘도 차가 뭉개지지 않을 만큼 벌어져 있을 것(구체 간격 값은 구현에서
   실측으로 정해 테스트에 적는다 — 값의 단일 출처는 테스트).
3. **잉크 대비**: 본문 잉크와 카드의 대비가 충분할 것(WCAG 4.5:1을 하한 기준으로 잡는다).
4. **청록 대비**: 확정 버튼의 청록 위 흰 글자, 그리고 육지 위 청록 점이 각각 읽힐 것.

## §5 바꾸지 않는 것

- 레이아웃(지도 왼쪽 + 상세 오른쪽) · 두 단계 선택(점 클릭 → 확정) · 점 크기 = 도시 규모 ·
  클릭 판 `HIT_SPAN` 불변식 — 전부 그대로. **색 파일과 색 클래스만 바뀐다.**
- 타입별 색 4종 금지 원칙 유지 — 청록은 선택·확정 표식이지 지역 분류가 아니다.
- 지도 데이터(`koreaMap.ts`)·지역 규칙 무변.

## §6 하지 않는 것 (YAGNI)

- HUD·사이드바·게임 내 카드의 밝은 전환 없음(④에서).
- 랜딩에 일러스트·로고·애니메이션 추가 없음 — 색 전환만.
- 다크 모드 대응 없음(이 게임은 단일 테마다).

## §7 미해결 (구현에서 판단)

- 청록의 최종 hex — 밝은 배경 위 실측 대비로 결정(§2).
- 카드 테두리 — 밝은 판에서 `border-frame`(어두운 토큰)을 대체할 값이 필요하다. 팔레트 모듈에
  테두리용 중간톤을 하나 두되, 육지 색과 겹쳐도 무해한지 실측으로 본다.
