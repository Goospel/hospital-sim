# T-087 · 폴딩 재사용은 슬롯 폭 확인을 면제하지 않는다

- **증상**: 2주차 PR A(주간 결산)에서 도착 시드를 `callSeed(week, day, minute, salt)`로 교체한 뒤, 인접 날의 도착 스트림이 바이트 동일하게 겹쳤다 — `(day d, minute m+97k) == (day d+k, minute m)`. 전수 26,880 튜플 중 78%가 충돌해 **매일이 전날의 97분 시프트**였다. 크래시도, 틀린 장부도 없어서 리뷰 프로브가 아니면 안 보였다.

- **원인**: `callSeed`의 슬롯 산술이 `(((week*7+day)*97 + index)*101 + salt)`라 **index 슬롯 폭이 97**인데, 그 자리에 0..479인 `minute`을 넣었다. 폭을 넘는 값은 이웃 날로 넘쳐 흐른다. 아이러니가 겹으로: ① `daysim.ts` 독스트링이 "index를 스트림 축으로 쓰지 마라"를 명시 경고했고 ② 교체 커밋의 주석 자체가 *"즉석 폴딩을 안 만드는 이유는 슬롯 폭 계산이 틀리면 조용히 충돌하기 때문 — callSeed가 이미 푼 문제"*라고 적으면서 정작 callSeed의 슬롯 폭을 확인하지 않았다. **검증된 함수의 재사용은 "그 함수가 무엇을 보장하는가"의 확인을 면제하지 않는다** — 보장은 인자 범위 계약 안에서만 성립한다.

- **해결**: 날 키를 먼저 해시한 뒤 분을 더하는 형태로 교체 — `dayBase = hash(callSeed(week, day, 0, salt) ^ worldMix)` 후 `dayBase + minute`. minute이 index 슬롯에 들어가지 않는다. 잠금 테스트 2건: 회귀 한 점(`arrivalSeed(d, 97) !== arrivalSeed(d+1, 0)`) + **전수 비겹침**(26,880 튜플 고유값 26,880 — 한 점만 잠그면 "그 쌍만 피하는" 폴딩도 통과하므로 스트림 전체 성질로 잠갔다).

- **재발방지**: 폴딩·해시 함수를 재사용할 때 ① 각 인자의 **슬롯 폭**을 독스트링/구현에서 확인하고 넣는 값의 범위와 대조한다 ② 스트림 축(연속 증가 값)은 폭이 보장된 슬롯에만 넣거나 키를 먼저 해시한 뒤 더한다 ③ 겹침 성질은 한 점이 아니라 **전수(또는 대표 구간 전수)**로 잠근다. [T-080](T-080.md)(green은 판별력의 증거가 아니다) 계열 — 이번 것은 "재사용은 검증의 증거가 아니다".
