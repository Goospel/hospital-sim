# T-086 · pane 미표시 = rAF 0프레임 — 실시간 검증은 프레임 공급원을 대체해서

- **증상**: `/sim`(rAF 루프 `useSimClock`)을 in-app 브라우저로 검증하는데 게임 시계가 전혀 돌지 않았다 — 4초간 rAF 콜백 **0회**(직접 계측). 스크린샷 API도 "pane is not displayed, not compositing frames"로 5초 타임아웃. 에러·경고는 없어서 처음엔 훅 결함으로 보였다.

- **원인**: Browser pane이 화면에 **표시되지 않은 상태**면 브라우저가 그 페이지의 컴포지팅을 중단하고 rAF 콜백을 아예 스케줄하지 않는다(절전 동작). 코드 결함이 아니라 환경 제약 — 같은 페이지를 pane이 보이는 세션에서 열면 정상 구동된다. 스크린샷 실패([T-034](T-034.md) 계열)도 같은 뿌리(합성 프레임 부재)다.

- **해결**: 검증 목적에 맞게 **프레임 공급원만 대체**했다 — 훅·`tick`·렌더는 실코드 그대로 두고 rAF 대신 `setTimeout` 구동으로 재마운트해, DOM 자동화로 수치를 검증(건설 비용·진료 수·금고 정합·배속 비율). 시각 증거(스크린샷)는 pane이 표시된 세션에서만 얻을 수 있다고 보고에 명시했다(검증한 것/못 한 것 분리).

- **해결 보강 — 추가 실측(2026-07-28 · PR C Task 5 UI 검증)**: 위 처방("rAF 대신 `setTimeout` 구동")이 **이번엔 듣지 않았다**. 숨은 pane에서는 rAF만 멎는 게 아니라 **연쇄 `setTimeout`도 1분에 한 번으로 조여진다**(백그라운드 타이머 throttling) — 그래서 setTimeout 재마운트는 게임 시계를 "정지"에서 "초당 한 틱 미만"으로 바꿀 뿐이라 7일 완주 같은 긴 시나리오가 사실상 불가능하다. 최종 처방은 한 단계 더 내려간다: **훅·`tick`·렌더는 실코드 그대로 두고 프레임을 직접 민다**(경과 250ms/프레임을 주입해 시계 함수를 호출) + 브라우저에 제어를 돌려줄 양보는 `setTimeout` 대신 **`MessageChannel`**(스로틀 대상이 아니다). 이 형태로 채용→건설→나흘 경과→포화→결산 사직까지 실측을 완주했다.

- **해결 보강 — 세 번째 얼굴: `ResizeObserver`(2026-07-29 · 화면 레이아웃 림월드화)**: 맵을 부모 크기에 맞춰 확대하는 `useFitScale`이 **배율 1에 머물렀다**. 옵저버가 잘못 붙은 줄 알고 대상 요소를 뜯어봤지만 host는 1600×770으로 정확히 잡혀 있었고, 브라우저 콘솔에서 `ResizeObserver`를 직접 만들어 같은 요소에 붙였더니 **300ms 동안 콜백 0회**였다 — 같은 자리에서 잰 `rAF`도 400ms에 0프레임, `document.visibilityState`는 `hidden`. **`ResizeObserver` 콜백은 렌더링 스텝(rAF 직후)에 발화하므로 rAF가 멎으면 함께 멎는다.** 즉 이 항목이 rAF·setTimeout에 이어 세 번째로 같은 뿌리를 드러낸 것이고, 여기서 얻은 교훈은 처방이 아니라 **오진 방지**다: 옵저버 기반 코드가 이 환경에서 초기값에 머무는 것은 **코드 결함이 아니다**.
  - 부수 효과로 코드가 실제로 좋아졌다 — 옵저버의 첫 콜백을 기다리지 말고 **마운트 시 `el.clientWidth`로 한 번 직접 재도록** 고쳤다(`getBoundingClientRect` 계열은 레이아웃을 즉시 계산하므로 컴포지팅과 무관하다). 실사용에서도 첫 프레임이 배율 1로 그려졌다 튀는 깜빡임이 사라진다. **다만 창 크기 변화 추적은 여전히 옵저버 몫이라, 숨은 pane에서 리사이즈 후의 재적합은 관측 불가로 남는다**(이번 검증에서 footer가 3줄로 늘었을 때 맵이 따라 줄지 않은 것이 그 잔여물이다 — 실브라우저에서는 발화한다).

- **재발방지**: rAF 기반 기능의 헤드리스(pane 미표시) 검증은 rAF 발화에 의존하지 말 것 — ① 시간 산술을 순수 함수(`minutesToTick`)로 분리해 vitest로 잠그고 ② 실브라우저 검증은 프레임 공급원 주입이 가능한 구조로 두며 ③ "시계가 안 돈다"가 보이면 코드보다 **pane 표시 여부부터** 확인한다. ④ **대체 프레임 공급원으로 `setTimeout`을 쓰지 않는다**(위 추가 실측) — 숨은 pane에서 함께 조여진다. 프레임을 직접 밀고, 양보가 필요하면 `MessageChannel`을 쓴다. ⑤ 처방을 쓸 때 "이 우회가 같은 뿌리(백그라운드 절전)에 걸리지 않는가"를 한 번 되묻는다 — 이 항목의 최초 처방이 바로 그 검사를 안 해서 한 세대 뒤에 무너졌다. ⑥ **렌더링 스텝에 묶인 콜백은 rAF만이 아니다** — `ResizeObserver`·`IntersectionObserver`도 같은 스텝에서 발화한다. 이 환경에서 그런 콜백이 안 오면 **코드를 의심하기 전에 `document.visibilityState`와 rAF 프레임 수부터 잰다**(두 줄이면 갈린다). 그리고 옵저버로 초기값을 정하는 코드는 **마운트 시 동기 측정을 함께 두는 것이 기본형**이다 — 첫 콜백을 기다리는 구조는 이 환경에서 영영 오지 않을 뿐 아니라, 실브라우저에서도 한 프레임의 깜빡임을 만든다.
