# T-093 · 값 임포트 순환 + 최상위 평가 = TDZ 시한폭탄 — 처방은 leaf 추출

- **증상**: 림월드형 재설계 PR C Task 2~3(2026-07-27~28)에서 욕구 모듈(`src/sim/needs.ts`)이 휴게실·식당 의자를 찾느라 `patientFlow`의 `furnitureSpots`를 **값으로** 임포트했다. 그런데 `patientFlow`는 이미 `needs`의 `starvedSlowFactor`를 값으로 당기고 있어 **실재하는 런타임 순환**이 됐다. 테스트는 894건 전부 green이고 dev·빌드도 정상이라 **아무 증상이 없었다** — 문제는 관측된 고장이 아니라 잠복이었다.

- **원인**: ESM은 순환 임포트 자체를 허용하고, 순환 안의 심볼이 **함수 선언**이면 호이스팅되어 실행 시점엔 이미 채워져 있다. 그래서 당장은 돈다. 무너지는 조건은 **모듈 최상위에서 평가되는 값**이다 — `needs.ts`의 `BREAKS` 표는 모듈 로드 시점에 평가되는 배열 리터럴이라, 여기에 좌표 파생(`furnitureSpots`)을 끌어다 넣는 순간 "아직 초기화되지 않은 바인딩" 접근이 되어 **TDZ(`ReferenceError: Cannot access before initialization`)로 즉사**한다. 더 나쁜 건 발현 조건이 **모듈 진입 순서**라는 것이다: vitest(파일별 진입)·dev(라우트 진입)·정적 export(빌드 순서)가 각각 다른 순서로 그래프에 들어가므로 **한 환경에서만 터지고 다른 환경은 멀쩡**할 수 있다. 그러면 원인이 "이 코드"가 아니라 "이 환경"으로 보여 추적이 길어진다.

- **해결**: 순환을 없앨 절단선을 **의미**가 아니라 **위상**으로 잡았다 — 순수 좌표 파생만 새 leaf 모듈 `src/sim/spots.ts`로 내렸다(`NEIGHBORS`·`frontTile`·`furnitureSpot`·`furnitureSpots` + 세 파일에 복제돼 있던 `samePt`·`ptKey`). `spots.ts`는 `world`·`path`만 임포트하는 leaf라 어느 쪽에서 당겨도 순환이 안 생긴다. **방 종류의 의미가 실린 함수는 안 옮겼다** — `waitingSeats`(대기실 좌석)는 `patientFlow`에 남겼다(이 파일의 경계는 "좌표를 어떻게 뽑는가"이지 "그 자리가 무엇인가"가 아니다). re-export는 두지 않고 호출부 5곳을 정직하게 갱신했다(re-export를 두면 출처가 흐려져 순환이 다시 자란다). 확정된 임포트 위상: `world/path → spots → fatigue → needs → patientFlow → emergency → day/week → tick`. 동작 변경 0이 계약이라 새 테스트도 돌연변이도 없다(894 green·tsc 0 유지 — 커밋 `d599fcf`).

- **재발방지**: ① **모듈 최상위에서 표·배열·객체를 평가하는 파일**은 임포트 순환의 뇌관이다 — 그런 파일에 값 임포트를 추가할 땐 상대 모듈이 나를 되당기는지 먼저 본다(`grep "from './<나>'"` 한 줄이면 된다) ② 두 모듈이 서로 필요하면 공통부를 **leaf 모듈로 내린다** — 절단선은 "무엇에 관한 코드인가"가 아니라 **"무엇에 의존하는가"**로 잡는다(순수 파생은 내리고, 도메인 의미가 실린 것은 남긴다) ③ 잘라낸 뒤 **임포트 위상을 파일 머리말에 한 줄로 못박는다** — 안 적으면 다음 사람이 편의상 re-export를 달아 순환을 되살린다(`spots.ts`·`needs.ts` 머리말이 그 자리다) ④ 이 종류의 결함은 **green이 무해를 증명하지 않는다**([T-080](T-080.md)·[T-091](T-091.md) 계열) — 순환은 "지금 터지는가"가 아니라 "무엇을 추가하면 터지는가"로 판정한다.
