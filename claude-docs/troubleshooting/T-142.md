# T-142 · CSS 필터가 테스트로 잠근 색 계약을 런타임에 우회한다

- **증상**: 랜딩 확정 버튼의 청록 배경은 `landingPalette.test.ts`가 흰 글자 WCAG 4.5:1을 잠근 값(`#327974`, 대비 5.09)인데, `hover:brightness-110`을 얹자 hover 상태에서 배경이 `#378580`으로 밝아져 대비 4.35로 **AA 미달**이 됐다. 테스트 1541건 전건 초록 — 팔레트에 그 값을 정적으로 넣었으면 테스트가 거부했을 색을, 필터가 런타임에 만들어 냈다.

- **원인**: 색 계약 테스트는 **팔레트 상수**를 재지만 CSS 필터는 **렌더 파이프라인**에서 그 값을 변형한다 — 변형 결과는 어느 테스트의 입력도 아니다. jsdom은 필터를 계산하지 않으므로 컴포넌트 테스트로도 결과색이 안 나온다. `brightness()`는 sRGB 채널 선형 배율이라(픽셀 실측으로 확정: `#327974 × 0.95 = #2f736e`가 스크린샷 픽셀과 일치) 밝히는 방향은 흰 글자 대비를 반드시 깎는다.

- **해결**: `hover:brightness-110` → `hover:brightness-95`. 어둡게 하는 방향은 흰 글자 대비가 **단조 상승**이라(5.09 → 5.52) 어떤 배율이든 계약을 못 깬다. 코드 주석에 세 수치(기본 5.094 / ×1.1 시 4.349 / ×0.95 시 5.522)를 남겨 다음 사람이 110으로 되돌리기 전에 읽게 했다. 브라우저에서 hover 픽셀을 찍어 `#2f736e` 일치를 확인했다.

- **재발방지**: **테스트로 잠근 색 위에 필터를 얹을 때는 "필터가 계약을 어느 방향으로 미는가"를 먼저 판정한다.** 계약이 단조 보존되는 방향(밝은 글자 위 배경이면 어둡게, 어두운 글자 위 배경이면 밝게)만 쓰면 배율과 무관하게 안전하다. 반대 방향이 꼭 필요하면 필터 결과색을 손으로 계산해 계약 여유 안인지 확인하고 그 수치를 주석으로 남긴다 — 이 계약은 구조적으로 테스트 밖이라 주석이 유일한 가드다(클래스 문자열을 긁는 테스트는 리팩터마다 깨지는 가짜 계측기라 기각했다).
