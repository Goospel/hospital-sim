# T-075 · 전면 레이어가 클릭을 삼킴 — pointer-events-none 누락 + JS .click() 검증의 맹점

- **증상**: 채용 데스크 v2(#113) 배포 후, SETUP에서 **빈 방을 눌러도 아무 일도 안 일어났다**("의사 채용 과정을 없앴니?"라는 실사용 피드백). 그런데 개발 중 브라우저 검증에선 방 클릭→오버레이가 "정상"으로 보였다.

- **원인**: [HospitalMap.tsx](../../src/components/HospitalMap.tsx)의 아바타 레이어 `<div className="absolute inset-0">`가 맵 전체를 덮는데 **`pointer-events-none`이 없었다**. 이 투명 레이어가 DOM 순서상 방 버튼(SETUP의 `onRoomClick`) **뒤에 렌더돼 위에 쌓여**, 실제 마우스 클릭을 전부 삼켰다. 형제 장식 레이어(보행자·조명)는 이미 `pointer-events-none`인데 아바타 레이어만 빠졌다. 진단은 `document.elementFromPoint(방버튼중앙)`이 버튼이 아니라 `DIV.absolute inset-0`을 반환하는 것으로 확정했다(8개 방 전부 `allBlocked`).

- **해결**: 아바타 레이어 컨테이너에 `pointer-events-none` 추가(아바타 스프라이트는 상호작용 없는 장식이라 레이어째 꺼도 잃는 게 없다). 수정 후 `elementFromPoint`가 방 버튼을 반환하고, 실제 좌표 클릭으로 방→오버레이→도장→예산→맵 아바타 전 흐름이 작동.

- **재발방지**: ① **전체를 덮는(`inset-0`/`fixed inset-0`) 장식·오버레이 레이어는 기본적으로 `pointer-events-none`** — 그 아래 무엇이든 클릭 대상이 있으면 조용히 막힌다. 형제 레이어들이 이미 `pointer-events-none`인데 하나만 빠졌다면 그게 범인. ② **더 중요한 교훈 — 브라우저 클릭 검증을 `element.click()`(JS)으로 하지 마라.** JS `.click()`은 히트테스트를 건너뛰고 핸들러를 직접 호출해 `pointer-events`·겹침·z-index로 가려진 버그를 **전부 우회**한다("작동함"으로 오판). 사용자와 같은 경로를 검증하려면 **좌표 기반 실제 클릭**(`computer left_click`)과 `elementFromPoint`로 "그 좌표의 최상단 요소가 정말 그 버튼인가"를 확인하라. 이 버그는 v2 검증이 JS `.click()`·DOM read였고 (브라우저 창이 숨겨져 스크린샷이 타임아웃돼) 실제 클릭을 한 번도 못 해서 배포됐다.
