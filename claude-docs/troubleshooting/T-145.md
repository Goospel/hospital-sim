# T-145 · 커버리지 겹침은 「지나는 코드」가 아니라 「단언하는 값」으로 판정한다

- **증상**: 배경 낮 전환에서 가로등의 지면 광원 웅덩이(방사형 그라디언트)를 제거했다. 그러자 「가로등이 있는 변형은 단색 원반이 아니라 방사형 그라디언트를 만든다」 테스트가 겨누던 대상이 사라져 보였고, *"이제 세는 그라디언트가 전부 발광 큐 것이라 아래 「발광 패스」 테스트와 측정 대상이 겹친다"*고 판단해 **삭제를 지시했다.** 실행자가 지시 전에 돌연변이로 승계를 확인했는데 — **승계가 없었다.**

- **원인**: 두 테스트가 같은 코드 구간(발광 flush)을 지나는 것을 「같은 규칙을 잠근다」로 오독했다. 실제로 「발광 패스」 테스트는 `calls.composites`만 단언한다 — `lighter` 진입과 `source-over` 복귀뿐이고 **그라디언트는 아예 안 본다.** 그리고 가로등은 웅덩이를 잃었을 뿐 여전히 같은 발광 큐에 햇빛 한 점을 넣고 있어, 지킬 대상이 사라진 게 아니라 「가로등 웅덩이」에서 「발광 flush의 감쇠」로 **옮겨간** 것이었다.

- **해결**: 삭제 대신 **취지를 다시 썼다** — 발광 큐의 그라디언트를 겨누도록. 판정 근거는 돌연변이다: 발광 flush의 `createRadialGradient`를 단색 `fillStyle`로 바꾸자 **그 테스트 1건만** 깨졌고(「발광 패스」 4건은 전부 통과 — 합성 모드 설정이 루프 *바깥*이라 루프 내부 변조에 무감각하다), 삭제했으면 발광 감쇠 전체가 무방비가 됐다.

- **재발방지**: **테스트를 지우기 전에 「누가 이 규칙을 승계하는가」를 돌연변이로 실측한다.** 코드 독해로 "저 테스트가 덮겠지"라고 판단하면 안 된다 — 겹침은 지나는 코드가 아니라 **단언하는 값**이 정하고, 그건 읽어서는 잘 안 보인다(같은 함수를 지나면서 완전히 다른 축을 재는 일이 흔하다). 절차: ⓐ 지우려는 테스트가 잡는 돌연변이를 하나 심는다 ⓑ **그 테스트를 지운 상태로** 전체를 돌린다 ⓒ 다른 테스트가 잡으면 삭제해도 되고, 아무도 안 잡으면 그 테스트가 유일한 가드다. [T-144](T-144.md)와 짝이다 — 그쪽은 「통과하는 단언이 아무것도 안 지킬 수 있다」이고 이쪽은 「지워도 되는 줄 알았는데 유일한 가드였다」로, 둘 다 **단언이 실제로 무는 것을 돌연변이로 재기 전까지는 모른다**는 같은 말이다.
