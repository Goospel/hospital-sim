# T-082 · 픽스처 동일값이 죽인 판별력 — 단정은 옳은데 데이터가 대조군이 아니었다

- **증상**: 서브에이전트 실행 이력 조회 스크립트(`show-subagent-runs.ps1`)에 돌연변이 확인을 돌렸더니 9종 중 **1종이 생존**했다. 조인 로직

  ```powershell
  agentType = if ($hit) { $hit.Meta.agentType } else { $r.subagentType }
  ```

  의 조건을 `if ($false)`로 바꿔 **meta.json 조회를 통째로 무력화**해도 테스트 17건이 전부 통과했다.

- **원인**: 단정문은 멀쩡했다(`$r.agentType -eq 'general-purpose'`). 문제는 **픽스처**였다 — 벨트 로그의 `subagentType`과 트랜스크립트 `meta.json`의 `agentType`에 **똑같이 `'general-purpose'`를 넣어 뒀다.** 실제 데이터에서 이 둘이 보통 같은 값이라 자연스럽게 그렇게 만들었는데, 그 순간 테스트는 "조인해서 meta에서 읽었는가"가 아니라 "둘 중 아무거나 읽었는가"를 재게 된다. 조인을 꺼도 폴백이 같은 값을 돌려주니 green이다.

  [T-080](T-080.md)과 같은 병이지만 **층이 다르다.** T-080은 *단정의 형태*(부등호·존재성)가 규칙을 구속하지 못한 경우고, 이건 단정이 정확한 등호인데 **테스트 데이터가 두 경로를 구분하지 못하게 만든** 경우다. 즉 판별력은 단정만의 성질이 아니라 **단정 × 입력**의 성질이다. 실제 값이 같다는 사실이 픽스처를 "현실적으로" 만들지만 동시에 **대조군을 지운다**.

- **해결**: 두 출처에 **다른 값**을 넣어 어느 쪽을 읽는지 드러냈다.
  - 픽스처의 `meta.json`은 `agentType = 'gp-from-meta'`, 로그는 `subagentType = 'general-purpose'`
  - 조인 성공 경로: `agentType`이 **`gp-from-meta`**여야 한다(= meta에서 읽었다는 증거)
  - 폴백 경로도 함께 잠갔다 — 트랜스크립트를 못 찾는 케이스에서 `agentType`이 **로그값**으로 떨어지는지 별도 단정

  이렇게 고치자 같은 돌연변이가 즉시 죽었고(9종 전부 사살), 테스트는 17 → 18건이 됐다.

- **재발방지**: **픽스처를 만들 때 "이 값이 두 경로에서 같으면, 경로를 구분할 수 있는가"를 묻는다.** 같으면 대조군이 없는 것이므로 일부러 다르게 만든다 — 현실성보다 판별력이 우선이다(현실성은 실호출 검증이 따로 맡는다). 폴백이 있는 코드는 **성공 경로와 폴백 경로를 쌍으로** 단정한다. 한쪽만 검증하면 나머지 한쪽이 조용히 모든 케이스를 처리하고 있어도 모른다.

  그리고 이 결함은 **돌연변이 확인 외에는 잡을 방법이 없었다** — 커버리지는 100%였고(그 줄은 실행된다), 테스트는 전부 green이었고, 코드 리뷰로도 "단정이 맞으니 통과"로 보인다. [T-080](T-080.md)이 계획서 규약으로 승격시킨 *"green 직후 규칙을 임시로 지워 빨개지는지 확인"*을 **테스트 데이터 축까지 확장**해야 한다: 규칙만 지워보는 게 아니라 **조회·조인·폴백 같은 경로 선택도 꺼 본다.**
