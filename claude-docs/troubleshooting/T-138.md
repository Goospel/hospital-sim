# T-138 · Git Bash의 GNU tar가 `C:\` 경로를 원격 호스트로 오인 → npm 전역 설치 실패

- **증상**: Bash 도구로 `npm i -g @higgsfield/cli`를 돌리자 postinstall(`node install.js`)이 exit 1로 죽었다. 로그는 `tar (child): Cannot connect to higgsfield\cli\vendor\hf_1.1.20_windows_amd64.tar.gz: resolve failed` + `gzip: stdin: unexpected end of file`. **"연결 실패"라 다운로드·네트워크 문제로 읽히지만 다운로드는 이미 끝나 있었고**, 실제로 죽은 곳은 받아둔 `.tar.gz`를 푸는 단계였다.

- **원인**: GNU tar는 아카이브 이름에 콜론이 있으면 그것을 **원격 아카이브**(`[user@]host:path`)로 보고 호스트 이름을 DNS 조회한다. `C:\Users\...`의 **드라이브 콜론**이 여기 걸린다. Git Bash의 `tar`는 `/usr/bin/tar`(GNU tar 1.35)이고, 이것이 PATH에서 Windows 기본 `C:\WINDOWS\system32\tar.exe`(bsdtar 3.8.4)를 가린다. 같은 명령이 PowerShell에서는 bsdtar로 잡혀 통과하므로, **셸에 따라 결과가 갈린다**. 실측으로 방아쇠를 분리했다:

  | 케이스 | 결과 |
  |---|---|
  | 드라이브 문자 O, `@` X | 실패 — `Cannot connect to C: resolve failed` |
  | 드라이브 문자 X(상대 경로), `@` O | **성공** |
  | 드라이브 문자 O, `@` O | 실패 — `Cannot connect to scope\vendor\t.tar.gz` |
  | 위와 동일 경로를 bsdtar로 | **성공** |

  → 방아쇠는 **드라이브 콜론 하나**이고 `@`는 무관하다. 다만 npm **스코프 패키지**(`@higgsfield`)라 경로에 `@`가 있으면 tar가 `user@host`로 한 번 더 쪼개서, 에러 메시지의 호스트 자리에 `C`가 아니라 **경로 조각**이 찍힌다 — 원인이 드라이브 문자임을 가리는 것은 이 부분이다.

- **해결**: 부분 설치 잔재를 제거(`npm uninstall -g @higgsfield/cli` + `node_modules\@higgsfield` 삭제)한 뒤 **PowerShell에서** `npm i -g @higgsfield/cli`를 재실행해 통과했다. 코드 수정이나 패키지 우회 없이 셸만 바꾸면 된다.

- **재발방지**: **postinstall에서 네이티브 바이너리를 내려받아 tar로 푸는 npm 전역 설치는 이 머신에서 PowerShell로 돌린다**(Bash 도구 아님). 이 함정은 특정 패키지가 아니라 "Windows에서 GNU tar에 절대경로를 넘기는 모든 스크립트"의 성질이라 재사용된다. 진단 측면에서는 **`Cannot connect` / `resolve failed`를 네트워크 장애로 읽지 않는다** — GNU tar에서는 경로 파싱 결과일 수 있고, 스코프 패키지에서는 메시지가 원인을 적극적으로 오도한다. 글로벌 `~/.claude/CLAUDE.md`의 「Windows 셸 한글·인코딩 원칙」과 같은 계열(셸 차이로 조용히 갈리는 실패)이라 **승격 후보**다.
