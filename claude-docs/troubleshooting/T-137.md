# T-137 · 돌연변이 확인 + `git checkout --` = 미커밋 구현 소실

- **증상**: A3(경증 쏠림) 구현 중 implementer 서브에이전트가 돌연변이 확인(코드를 일부러 변조해 테스트가 죽는지 실측)을 하고 `git checkout -- <file>`로 되돌렸더니, **변조만이 아니라 아직 커밋하지 않은 구현 전체가 함께 사라졌다**(events.ts를 다시 써야 했다).

- **원인**: `git checkout -- <file>`(및 `git restore`)의 복원 기준은 HEAD(또는 인덱스)다. 미커밋 상태에서는 "방금 넣은 변조 한 줄"과 "오늘 작성한 구현 전부"가 git에게 같은 것 — HEAD 이후의 워킹트리 변경 — 이라 구별 없이 지워진다. 돌연변이 확인은 정의상 *고치고 되돌리기*를 반복하는 작업이라 이 명령이 자연스럽게 손에 잡히는데, 그 자연스러움이 함정의 방향이다.

- **해결**: 구현을 먼저 커밋한 뒤 돌연변이 실험을 돌렸다(소실분은 재작성으로 복구). 커밋이 있으면 `checkout --`의 복원 지점이 정확히 "실험 직전"이 된다.

- **재발방지**: **돌연변이 확인은 커밋 후에만 시작한다** — 커밋이 곧 실험의 복원 지점이다. 대안(stash·파일 백업)은 실험 반복 중 잊기 쉬워 규칙으로 삼지 않는다. 서브에이전트에게 돌연변이 확인을 시킬 때는 위임 프롬프트에 "변조 전 `git status`로 전부 커밋됐는지 확인"을 명시한다(이번 세션의 리뷰어 프롬프트부터 적용).
