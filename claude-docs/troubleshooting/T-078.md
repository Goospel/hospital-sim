# T-078 · block-fable-implement 훅이 Opus 서브에이전트를 오탐한다 — 부모 트랜스크립트에 서브에이전트 턴이 없다

- **증상**: Fable 세션(피로 승격, 2026-07-25)이 규칙대로 구현을 Opus 서브에이전트(Agent 도구, `model: 'opus'`)에 위임했는데, 서브에이전트의 첫 `Edit` 호출부터 전부 *"Fable 세션은 설계 전용 — 코드 편집 차단"* 으로 거부됐다. 훅 안내문이 제시하는 탈출구가 바로 "Opus 서브에이전트에 위임하라"인데, 그 경로가 막힌 것.

- **원인**: `~/.claude/hooks/block-fable-implement.ps1`은 `transcript_path` 꼬리에서 **마지막 assistant 항목의 `message.model`** 을 읽어 현재 모델을 판정한다. 훅 주석의 전제는 "서브에이전트 항목도 같은 트랜스크립트에 순서대로 적히므로 그 시점 모델이 opus로 잡힌다"였다. **이 하네스 버전에서 그 전제가 거짓이다** — 서브에이전트 턴은 부모 트랜스크립트에 기록되지 않는다(실측: 서브에이전트 작업 중 tail 100줄 전부 `"model":"claude-fable-5"`, `isSidechain=False`). 그래서 서브에이전트가 편집할 때도 훅은 항상 부모(Fable)를 본다.

- **해결**: 훅·설정 파일은 사용자 승인 영역이라 건드리지 않았다. 서브에이전트가 스크래치패드에 Node 패치 스크립트를 써서 Bash로 실행해 파일을 갱신했다 — CRLF·UTF-8(BOM 여부 포함) 보존, 앵커 문자열 1회 매칭 강제, 패치 후 diff로 검증. 결과물은 전량 게이트(tsc·vitest·lint)로 확인했다.

- **재발방지**: ① **훅 수정은 사용자 판단 사항(승격 후보)** — 부모 트랜스크립트에 서브에이전트를 식별할 신호 자체가 없어서, 트랜스크립트만 읽는 현 설계로는 구분이 원리적으로 불가능하다. 후보: 서브에이전트 컨텍스트를 알리는 다른 신호원(환경변수 등)을 찾거나, "마지막 assistant 항목이 오래됐으면(=지금 도구를 부르는 주체가 그 항목이 아닐 수 있으면) 통과" 같은 보수적 완화. ② 훅이 고쳐질 때까지, Fable 세션이 구현을 위임할 땐 **서브에이전트 프롬프트에 이 오탐과 우회 절차(Node 패치 + 인코딩 보존 + diff 검증)를 명시**한다 — 서브에이전트가 차단에 부딪혀 헤매는 시간을 없앤다. ③ 우회로 파일을 갱신했을 땐 반드시 전량 게이트로 검증한다(Edit 도구의 안전장치를 안 거치므로).
