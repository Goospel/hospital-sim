# T-078 · block-fable-implement 훅이 Opus 서브에이전트를 오탐한다 — 부모 트랜스크립트에 서브에이전트 턴이 없다

- **증상**: Fable 세션(피로 승격, 2026-07-25)이 규칙대로 구현을 Opus 서브에이전트(Agent 도구, `model: 'opus'`)에 위임했는데, 서브에이전트의 첫 `Edit` 호출부터 전부 *"Fable 세션은 설계 전용 — 코드 편집 차단"* 으로 거부됐다. 훅 안내문이 제시하는 탈출구가 바로 "Opus 서브에이전트에 위임하라"인데, 그 경로가 막힌 것.

- **원인**: `~/.claude/hooks/block-fable-implement.ps1`은 `transcript_path` 꼬리에서 **마지막 assistant 항목의 `message.model`** 을 읽어 현재 모델을 판정한다. 훅 주석의 전제는 "서브에이전트 항목도 같은 트랜스크립트에 순서대로 적히므로 그 시점 모델이 opus로 잡힌다"였다. **이 하네스 버전에서 그 전제가 거짓이다** — 서브에이전트 턴은 부모 트랜스크립트에 기록되지 않는다(실측: 서브에이전트 작업 중 tail 100줄 전부 `"model":"claude-fable-5"`, `isSidechain=False`). 그래서 서브에이전트가 편집할 때도 훅은 항상 부모(Fable)를 본다.

- **해결**: 트랜스크립트가 아니라 **`PreToolUse` 입력의 `agent_id`**로 판별하도록 고쳤다 — `if ($data.agent_id) { exit 0 }` 한 줄. 계측(디버그 훅으로 부모/서브에이전트 입력 전수 비교)에서 확인한 사실: 서브에이전트 호출에만 `agent_id`·`agent_type`이 실리고, `session_id`·`transcript_path`·`CLAUDE_*` 환경변수는 **부모와 완전히 동일**하다(그래서 옛 판정법은 원리적으로 불가였다). 호출 단위 판별이라 위임 중에도 부모의 직접 편집은 여전히 차단된다. positive control 4종(Fable+코드=DENY / Fable+서브=PASS / Fable+.md=PASS / Opus+코드=PASS) 통과. 설계·계측 기록은 글로벌 레포 `docs/2026-07-25-fable-hook-subagent-fix-design.md`.

  > 수정 전 당시엔 이렇게 우회했다(기록 보존): 훅·설정 파일은 사용자 승인 영역이라 건드리지 않고, 서브에이전트가 스크래치패드에 Node 패치 스크립트를 써서 Bash로 실행해 파일을 갱신했다 — CRLF·UTF-8(BOM 여부 포함) 보존, 앵커 문자열 1회 매칭 강제, 패치 후 diff로 검증. Edit 도구의 안전장치를 안 거치므로 결과물은 전량 게이트(tsc·vitest·lint)로 확인했다.

- **재발방지**: ① **훅이 "지금 부른 주체"를 판정할 땐 트랜스크립트 유추가 아니라 훅 입력이 직접 주는 필드를 쓴다** — 트랜스크립트는 *무엇이 기록됐나*를 말할 뿐 *누가 지금 부르나*를 말하지 않고, 그 간극이 이 오탐의 근인이었다. 새 판정 로직을 짜기 전에 **계측 훅으로 입력 전수를 한 번 찍어 본다**(문서에 없는 필드가 실제로 온다 — `agent_id`가 그랬다). ② **탈출구를 안내하는 가드는 그 탈출구가 실제로 열리는지 검증한다** — 이 훅은 "Opus 서브에이전트에 위임하세요"라고 안내하면서 그 경로를 스스로 막고 있었고, 안내문만 보고는 아무도 몰랐다. ③ **가드를 고칠 땐 통과뿐 아니라 차단도 실측한다**(positive control) — 통과만 확인하면 가드를 죽여 놓고 "고쳤다"고 할 수 있다(T-045 계열). ④ 곁다리로 의심했던 한글 인코딩 취약성(stdin CP949 → 파싱 실패 → fail-open)은 **오탐**이었다: 운영 훅을 직접 호출해 한글 입력에서 정상 차단됨을 확인했고, 첫 징후는 계측기가 stdin을 이중 포장해 저장한 아티팩트였다 — **계측기 결함을 대상 결함으로 오인하지 않으려면 대상을 직접 때려 본다**.
