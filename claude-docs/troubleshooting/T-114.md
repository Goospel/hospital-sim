# T-114 · 숨은 Browser pane에서 잰 계산색은 **트랜지션 시작값**이다

- **증상**: 지역 선택 지도(RegionPicker)에서 선택된 점의 색을 검증하는데, DOM은 분명히 `class="block transition-colors bg-on-desk"`인데 `getComputedStyle(el).backgroundColor`가 `rgb(122,116,96)`(= `on-desk-muted`, **선택 안 된 색**)을 돌려줬다. `aria-pressed`는 `true`, 옆 패널 텍스트도 그 지역으로 바뀐 상태였다.

  결정적으로 헷갈렸던 것: **같은 버튼 안에 `bg-on-desk` 프로브를 새로 붙이면 정상색**(`rgb(216,207,175)`)이 나왔다. 같은 부모·같은 태그·같은 클래스인데 결과가 갈리니 "Tailwind가 그 클래스를 안 만들었나" → "변수가 어디서 덮였나" → "시트 순서 문제인가"로 30분 넘게 샜다. 스타일시트를 훑어도 `bg-on-desk` 규칙이 **하나도 안 잡혀서**(뒤에 나오듯 이 관측 자체가 헛다리였다) 더 확신이 갔다.

- **원인**: **Browser pane이 표시되지 않으면 페이지가 프레임을 합성하지 않고, 그래서 `document.timeline`이 흐르지 않는다.** 그 상태에서 클래스가 바뀌면 CSS 트랜지션이 생성은 되는데 `currentTime: 0`에 멈춘 채 `playState: "running"`으로 남는다. Tailwind의 `transition-colors`는 `fill: backwards`라 **시작값(이전 색)이 계산값으로 보고된다**.

  ```js
  el.getAnimations()
  // [{ type:'CSSTransition', prop:'background-color', playState:'running',
  //    currentTime: 0, timing:{ duration:150, fill:'backwards', ... } }]

  const t0 = document.timeline.currentTime, p0 = performance.now()
  await new Promise(r => setTimeout(r, 600))
  document.timeline.currentTime - t0   // 0        ← 타임라인은 안 흐르고
  performance.now() - p0               // 844      ← 벽시계만 흐른다
  document.hidden                      // true
  ```

  새로 붙인 프로브가 정상색이었던 이유도 이걸로 설명된다 — **트랜지션은 값이 *바뀔* 때만 생긴다.** 처음부터 그 색으로 붙은 요소에는 트랜지션이 없어 계산값이 곧 최종값이다. 즉 "같은 클래스인데 다르다"는 클래스 문제가 아니라 **한쪽에만 멈춘 트랜지션이 얹혀 있다**는 뜻이었다.

  스타일시트 순회가 `bg-on-desk` 규칙을 0건으로 답한 것은 별개의 헛다리다(Tailwind v4의 레이어 구조를 내 순회가 못 훑었다). 이 거짓 신호가 잘못된 가설을 붙잡게 만들었다 — **한 번에 두 가지를 관측하면 어느 쪽이 거짓인지 모른다.**

- **해결**: 색을 재기 전에 애니메이션을 끝으로 민다. 취소(`cancel()`)해도 되지만 `finish()`가 "트랜지션이 끝난 뒤의 화면"이라는 의도에 더 맞는다.

  ```js
  document.querySelectorAll('*').forEach(el => el.getAnimations().forEach(a => a.finish()))
  // 이제 getComputedStyle이 최종색을 준다 — 선택점 rgb(216,207,175) · 비선택점 rgb(122,116,96)
  ```

- **재발방지**: 숨은 pane에서 화면을 검증할 때는 **계산 스타일을 그대로 믿지 않는다.** 이 프로젝트의 검수 절차([[background-concept-status]]의 "배포 화면 검수")는 이미 *"`requestAnimationFrame` 콜백이 안 오므로 `setTimeout`을 쓴다"*를 담고 있는데, 그것과 **원인이 같다**(합성 정지). 같은 뿌리에서 나온 두 번째 증상이므로 절차에 한 줄을 더한다:

  1. rAF 대신 `setTimeout`으로 기다린다 (기존)
  2. **색·크기를 재기 전에 `getAnimations().finish()`** (이 항목)

  그리고 더 일반적으로: **트랜지션이 걸린 속성은 "클래스"로 검증하고 "계산색"으로는 검증하지 않는다.** `el.className`에 `bg-on-desk`가 있는지는 타임라인과 무관하게 참이다. 계산색은 그 클래스가 *실제로 그 색을 뜻하는지* 확인할 때만 쓰고, 그때는 위처럼 트랜지션을 걷어낸다.
