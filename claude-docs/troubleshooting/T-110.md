# T-110 · 워크트리에서 `gh pr merge --delete-branch` 가 반만 수행된다

- **증상**: 워크트리에서 `gh pr merge <N> --squash --delete-branch` 를 돌리자 출력이 에러 한 줄뿐 — `failed to run git: fatal: 'main' is already used by worktree at 'C:/Users/kimsa/ClodeProjects/Hospital-sim'`. 성공 메시지가 없어 **머지 자체가 실패한 것처럼 보이는데, 실제로는 머지가 이미 끝나 있었다**(`gh pr view --json state` → `MERGED`). 대신 원격 브랜치는 삭제되지 않고 그대로 남았다.

- **원인**: `--delete-branch` 는 단일 동작이 아니라 **머지 → 로컬 main으로 checkout → 로컬 브랜치 삭제 → 원격 브랜치 삭제** 순서의 복합 절차다. 지금 작업 트리는 하네스가 만든 워크트리이고 `main` 은 메인 저장소 워크트리가 이미 점유하고 있어 두 번째 단계(checkout)에서 git이 거부한다. gh는 거기서 중단하므로 **1단계는 반영되고 4단계는 실행되지 않는다** — 부분 성공이 에러 하나로 보고되는 형태다. 워크트리를 상시 쓰는 이 환경에서는 예외가 아니라 기본 경로다.

- **해결**: 에러를 보면 먼저 `gh pr view <N> --json state,mergeCommit` 으로 머지 성공 여부를 확인하고(대개 `MERGED`), 남은 원격 브랜치를 `git push origin --delete <branch>` 로 직접 지운다. 로컬 브랜치는 워크트리가 체크아웃 중이라 지울 수 없으므로 그대로 둔다(하네스가 워크트리를 정리할 때 함께 사라진다).

- **재발방지**: 워크트리에서 머지할 때는 `--delete-branch` 의 성공을 신뢰하지 않는다. 머지 후 **`git ls-remote --heads origin <branch>` 로 원격 브랜치가 실제로 사라졌는지 확인**하는 것을 마무리 절차에 포함한다 — 안 지워진 브랜치는 아무 에러도 내지 않고 쌓이기만 해서 다음에 볼 사람이 없다. 애초에 `--delete-branch` 를 빼고 머지한 뒤 원격 삭제를 명시적으로 한 번 더 치는 편이 상태가 분명하다. 같은 이유로 **exit code 만 보고 "머지 실패"로 결론내지 않는다** — 이 명령은 부분 성공을 실패로 보고한다.
