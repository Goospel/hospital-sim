# T-143 · superpowers 문서에서 claude-docs 링크는 ../../../다 (../../가 아니다)

- **증상**: `docs/superpowers/plans/2026-07-31-bright-landing.md`와 `docs/superpowers/specs/2026-08-01-bright-hud-design.md`에서 T-142를 `[T-142](../../claude-docs/troubleshooting/T-142.md)`로 링크했더니 pre-commit이 `LINKS-CHECK: MISSING(1)`로 커밋을 **거부**했다. 같은 실수를 이틀에 걸쳐 두 번 밟았다.

- **원인**: `docs/superpowers/specs/` 는 저장소 루트에서 **3단계**(`docs` → `superpowers` → `specs`)라 루트로 올라가려면 `../../../`가 필요한데, 자주 쓰는 `claude-docs/troubleshooting/T-###.md`(2단계)의 감각으로 `../../`를 썼다. 두 경로가 다 "문서 폴더"라 깊이 차이가 눈에 안 들어온다. 게다가 마크다운 링크는 **깨져도 파일 안에서는 멀쩡해 보인다** — 편집 중에는 아무 신호가 없고 커밋 시점에야 검사기가 잡는다.

- **해결**: `../../../claude-docs/troubleshooting/T-###.md`. 같은 폴더 안의 다른 spec을 가리킬 때는 `(2026-07-31-….md)`, plans↔specs는 `(../specs/….md)`가 맞다 — 깊이는 **가리키는 쪽이 아니라 출발 폴더**가 정한다.

- **재발방지**: superpowers 문서에서 `claude-docs/`를 링크할 일이 생기면 **기존 문서의 링크를 복사해 경로만 바꾼다** — 예: 같은 폴더의 다른 plan에 이미 있는 `../../../claude-docs/...` 한 줄. 손으로 `../`를 세는 순간 이 함정이 다시 열린다. 검사기(`LINKS-CHECK`)가 이미 하드가드라 조용히 새지는 않으므로 이 항목은 **비용(실패한 커밋 재시도)을 줄이는 메모**지, 안전을 만드는 장치가 아니다.
