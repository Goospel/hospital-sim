# T-112 · 돌연변이 원복에 `git checkout --`을 쓰면 커밋 안 한 구현이 같이 지워진다

- **증상**: 새로 만든 `deptMixText`(미커밋)에 돌연변이 3종을 연속으로 심는 루프를 돌렸다. 원복은 T-108 규약대로 매 항목 끝에 걸어 뒀다:

  ```bash
  for m in slice tiebreak dev; do
    python -c "...심기..." $m
    npx vitest run src/components/simHud.test.ts
    git checkout -- src/components/simHud.ts      # ← 원복
  done
  ```

  첫 항목(`slice`)은 정상이었다 — 돌연변이가 심겼고 테스트가 죽었다. 그런데 2·3번째는 `AssertionError`로 **심기 자체가 실패**했다(`s.count(old) == 1`이 거짓). 확인해 보니 `git status`에 `src/components/simHud.ts`가 아예 **없었다**. 구현 60여 줄과 import 2줄이 통째로 사라진 것이다.

- **원인**: `git checkout -- <file>`은 워킹 트리를 **HEAD(또는 인덱스)로** 되돌린다. 「돌연변이 직전 상태」로 되돌리는 것이 아니다. 이번 baseline은 아직 커밋되지 않은 구현이었으므로 HEAD에는 `deptMixText`가 존재하지 않았고, 첫 원복이 돌연변이와 **구현을 함께** 지웠다. 2·3번째 반복은 이미 빈 파일 위에서 패치 대상을 못 찾은 것이다.

  T-108이 *"원복은 `finally`에 둔다"*까지는 잡아 뒀지만 **원복의 *기준*이 무엇인가**는 안 적혀 있었다. 그리고 실패가 조용했다: 심기 실패는 파이썬 트레이스백으로 요란하게 찍히는데, 그건 *"패치가 안 맞는다"*로 읽히지 *"내 구현이 사라졌다"*로는 안 읽힌다 — T-108이 지적한 것과 **정확히 같은 형태의 오독**이다(실패 모드가 출력에 안 적히는 자리에 있다).

- **해결**: 원복 기준을 **파일 사본**으로 바꿨다. HEAD를 안 거치므로 baseline이 커밋됐든 안 됐든 똑같이 동작한다.

  ```bash
  B="$TEMP/simHud.bak.ts"; cp src/components/simHud.ts "$B"
  trap 'cp "$B" src/components/simHud.ts; rm -f "$B"' EXIT
  for m in ...; do 심기; 실행; cp "$B" src/components/simHud.ts; done
  ```

  사라진 구현은 다시 작성했고(같은 내용), 이후 3종 돌연변이가 전부 정상적으로 사살됐다.

- **재발방지**:
  - **돌연변이·프로브의 원복은 `cp` 사본으로 한다.** `git checkout --`·`git restore`·`git stash`는 전부 **HEAD 기준**이라 미커밋 baseline을 지운다. 돌연변이 확인은 정의상 *"방금 쓴, 아직 커밋 안 한 코드"*를 대상으로 하므로 이 조합이 기본값 쪽으로 기울어 있다.
  - **대안: 돌연변이를 심기 전에 먼저 커밋한다.** 그러면 `git checkout --`이 맞는 도구가 된다. 어느 쪽이든 *"HEAD와 baseline이 같은가"*를 먼저 답하고 도구를 고른다.
  - `cp` 사본 방식은 **바이너리 복사**라 CRLF·BOM도 보존된다 — 파이썬 재작성이 EOL을 갈아 치우는 함정(글로벌 「Windows 셸 원칙」 3번)까지 같이 피한다.
