# T-139 · 돌연변이를 스크립트로 심으면 CRLF 파일에서 무성 실패한다 — 계측 결과가 뒤집힌다

- **증상**: 밝은 아트 디렉션 브랜치에서 두 번 났다. ⓐ `perl -0pi -e 's/.../.../'`로 조명 계수에 돌연변이를 심고 테스트를 돌렸더니 전부 초록이었다 — 하마터면 **"이 단언은 돌연변이를 못 잡는다"**로 결론 낼 뻔했다. 실제로는 치환이 **0건**이었다(`grep -c`로 치환 여부를 따로 세어 잡았다). ⓑ 다른 돌연변이를 python 텍스트 재작성으로 적용했더니 `TileMap.tsx`가 **CRLF → LF로 통째로 뒤집혀** 되돌리는 데 시간을 썼다.

- **원인**: 이 저장소는 `core.autocrlf=true`라 워킹트리 파일이 **CRLF**다. ⓐ `perl -0`(슬럽 모드)로 읽은 내용의 줄 끝은 `\r\n`인데 패턴에는 `\n`만 적혀 있어 여러 줄에 걸친 패턴이 아무 데도 안 맞는다 — perl은 "0건 치환"을 **성공(exit 0)**으로 보고한다. ⓑ 파이썬 `open().read()` → `write()`는 줄 끝을 `\n`으로 정규화해 되돌려 쓴다.

- **해결**: ⓐ는 `grep -c`로 치환이 실제로 일어났는지 세어 0건임을 확인하고 Edit 도구 부분 편집으로 다시 심었다 — 그러자 단언이 정상적으로 죽었다(돌연변이는 사살됐다). ⓑ는 파일을 복원하고 같은 방식으로 바꿨다.

- **재발방지**: **돌연변이는 텍스트 재작성 스크립트가 아니라 Edit 도구 부분 편집으로 심는다** — 실패하면 에러가 나므로 무성 실패가 구조적으로 불가능하고 줄 끝도 안 건드린다. 스크립트를 굳이 써야 하면 **심은 직후 치환이 실제로 됐는지 센다**(`grep -c '<변조 후 문자열>' <파일>` 또는 `git diff --stat`이 그 파일을 들었는지) — **테스트 결과를 보기 전에** 한다. 되돌린 뒤에는 `git status` 클린 + `git hash-object <파일>`이 HEAD blob과 일치하는지까지 본다(눈으로 보는 diff 0줄은 줄 끝 뒤집힘을 못 잡는다). 글로벌 「파일 재생성 시 BOM·EOL 보존」과 **결이 다른 함정이라 따로 적는다**: 그쪽은 *산출물이 깨진다*이고 이건 **계측 결과가 정반대로 뒤집힌다** — 돌연변이가 안 심겼는데 "테스트가 못 잡는다"로 읽혀, 멀쩡한 단언을 고치러 가게 만든다.
